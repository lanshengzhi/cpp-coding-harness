# Own the scoped pi-agent-core Agent and Agent Turn capabilities

The Agent and Agent Turn capabilities the three scoped provider paths require are a pi capability subset by omission only, consumed through the frozen pi-ai `streamSimple` surface: harness stream flow (per-turn option set plus the terminal-error-event contract), seven-level thinking with a `medium` default and capability clamping, read/bash/edit/write tool execution with pi names, compaction with `cacheRetention:"none"` summarization and overflow/threshold/manual triggers, the full eleven-entry-type pi v3 session-state contract with #327 resume re-resolution, and terminal-error/re-auth-guidance/turn-auto-retry error propagation. This implements parity-map ticket [#331](https://github.com/lanshengzhi/cpp-coding-harness/issues/331), consuming the handoff frozen by [#330](https://github.com/lanshengzhi/cpp-coding-harness/issues/330) and the pi-ai contracts of [#326](https://github.com/lanshengzhi/cpp-coding-harness/issues/326)–[#329](https://github.com/lanshengzhi/cpp-coding-harness/issues/329).

> Injection clauses superseded by [ADR 0040](0040-own-asynchronous-operations-and-the-serialized-runtime-lifecycle.md): the Agent no longer depends directly on an injected or virtual-for-fake coding-agent `ModelRuntime::streamSimple`. It owns an AI-owned move-only `ModelStream` operation by value, returning `AsyncResult`; coding-agent Models Runtime remains concrete. The fake-`ModelRuntime` evidence seam below is likewise superseded: option-forwarding evidence uses the `ModelStream` value and fake Provider behavior. The `streamSimple` option set, event ordering, terminal outcomes, thinking, Tool, compaction, Session Entry, cancellation, re-auth, retry semantics, and their behavioral evidence remain authoritative.

## Considered options

- Treat the Agent as a stateless loop wrapper over the provider client: rejected — the current `ai::StreamingChatClient`/`OpenAIChatClient` approximation and `Model{id}` placeholder predate the pi alignment and cannot express the frozen `streamSimple` option surface, terminal-error contract, or kDefaultModel-to-real-model resolution.
- Keep C++ thinking defaults (`"off"`, levels off..xhigh): rejected — pi defaults to `"medium"` with `"max"` in the level set; a new session's first turn must carry the same reasoning semantics as pi.
- Keep `edit_file` as the built-in tool name: rejected — pi's model-facing tool is `edit` with edit-diff semantics; names are part of the observable contract.
- Defer compaction triggers to pi-coding-agent: rejected — overflow recovery is part of pi's normal post-turn loop; a long session (DeepSeek's modest context window especially) observably diverges at overflow without it, and the ticket's question names the `cacheRetention:"none"` flow.
- Claim a subset of session entry types and Defer `branch_summary`/`custom`/`custom_message`/`label`/`session_info`: rejected by HITL override — the pi v3 session format is an interoperable wire contract (ADR 0009), so all eleven entry types round-trip with pi's projection semantics even though their producers (tree navigation, extensions, session naming) remain fog.
- Keep turn auto-retry deferred to pi-coding-agent: rejected — retry defaults on in pi (`maxRetries` 3, `baseDelayMs` 2000) and is part of the error/cancellation propagation the ticket names.
- Claim the high-level `AgentHarness` class surface (Session interface, hooks, resources, skills/prompt templates, tree navigation): rejected — pi's own coding-agent drives the low-level `Agent` directly; the components map to already-claimed capabilities or fog, and claiming the class would drag extension hooks and tree navigation into this module.

## Consequences

- **Harness stream flow via `streamSimple` is Supported.** The Agent consumes `ModelRuntime::streamSimple` with the pi harness consumer's option set (`reasoning`, `sessionId`, `cacheRetention` default `"short"`, `timeoutMs`, `maxRetries`, `maxRetryDelayMs`, `headers`, `signal`); `transport` is fixed per adapter and `metadata`/`onPayload`/`onResponse`/`thinkingBudgets` stay omitted per #329. Terminal-error-event semantics per #326: exactly one `error`/`aborted` terminal event plus a final AssistantMessage with `stopReason`/`errorMessage`; the six-category channel (`model_source`, `model_validation`, `provider`, `stream`, `auth`, `oauth`) flows through the single `util::Expected` channel. Loop lifecycle order per ADR 0014 (turn_end → prepare-next-turn → stop-after-turn → steering → follow-up).
- **Thinking levels are Supported and aligned:** seven levels including `"max"`, default `"medium"`, `kDefaultModel` until session assembly resolves the first real model (CLI → scoped → resume → settings default → first available with configured auth), creation/switch clamping via pi-ai's `getSupportedThinkingLevels`/`clampThinkingLevel`, per-turn `reasoning` as `off → undefined`, persistence as `thinking_level_change` entry plus settings default.
- **Tool execution is Supported:** JSON Schema argument validation, `beforeToolCall`/`afterToolCall` hooks, default parallel execution with per-tool sequential override, `length`-truncated messages fail every tool call, tool-result grouping with `is_error`, per-call failure isolation, all-true `terminate` batch hint. Built-in set is pi's default `read`/`bash`/`edit`/`write` with pi-aligned names (`edit` replaces `edit_file`; edit-diff semantics aligned to frozen source at implementation). `grep`/`find`/`ls` are Deferred with no placeholder.
- **Compaction is Supported (machinery and triggers):** cut-point selection (`keepRecentTokens` 20000) with split-turn handling, summarization via `cacheRetention:"none"` and a fresh session id, `CompactionEntry` persistence and context rebuild; overflow (compact and retry once), threshold (`contextWindow − reserveTokens(16384)`), and manual (abort then compact) triggers; settings defaults `enabled: true`/`16384`/`20000`.
- **Session state is Supported across all eleven pi v3 entry types** with pi's field/null/ordering/active-path and context-projection semantics (`custom` omitted from model context by default, `custom_message` → CustomMessage, `branch_summary` → branchSummary message, `compaction` → compactionSummary + retained tail, `label` → `getLabel`, `session_info` → name); `buildSessionContext` derives thinking/model/tools; resume re-resolves only `model_change {provider, modelId}` against the live runtime per #327. Producers (tree navigation, extensions, session naming) remain fog.
- **Error/cancellation propagation is Supported:** terminal semantics and six-category channel per #326; re-auth guidance with pi's two branches (no key → "No API key found for X … Use /login…"; OAuth expired → "Credentials may have expired … Run '/login X'") at preflight and request time; turn auto-retry with pi defaults (enabled, `maxRetries` 3, `baseDelayMs` 2000, exponential backoff, quota/billing and overflow excluded, failed message removed from live state but retained in session history, abort-interruptible backoff, `auto_retry_start`/`auto_retry_end` events).
- **Residual dispositions:** R1–R7 aligned under the above; R8–R11 verified already aligned (event surface/lifecycle, terminal fields, queue modes, 11-type parsing); R12 bounded queues remain the recorded ADR 0022 divergence; R13 six-category terminal payload stays a recorded #326 enrichment; R14 no default turn limit stays ADR 0015; R15 the `AgentHarness` class is Deferred.
- **Evidence gate per #330:** capability-to-source mapping per Supported Capability (checklist in `fixtures/pi-agent-core/README.md`), lifecycle/ordering/cancellation tests plus goldens on every deterministic surface (loop ordering, a streamSimple option-forwarding golden via a fake `ModelRuntime`, thinking clamp/resolution tests and persistence goldens, tool ordering/validation/truncated-fail-all/terminate/is_error tests, compaction cut-point and `cacheRetention:"none"` request goldens plus overflow/threshold lifecycle tests, an 11-entry-type JSONL round-trip golden with resume re-resolution tests, cancellation tests, the six-category terminal matrix, verbatim re-auth-guidance goldens, retry lifecycle tests). A committed `fixtures/pi-agent-core/` directory mirrors the #330 `fixtures/pi-ai/` pattern. E2E belongs to the pi-tui / pi-coding-agent gates.
