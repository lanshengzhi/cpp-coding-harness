# Own the pi-aligned main-screen scrollback flow for the TUI Toolkit renderer

The TUI Toolkit's main-screen differential renderer previously clipped the composed buffer to the terminal viewport (`new_lines.resize(rows)`) and rewrote rows in place with absolute cursor addressing, so TUI content never entered the terminal's native scrollback: users could not scroll up to review earlier conversation, and the startup header/loaded-resources block stayed pinned at the top of the screen instead of scrolling away as content grew. ADR 0035 claimed the "TUI core with main-screen differential renderer" as a Supported Capability without recording this divergence from pi's `TuiMainScreen`, whose contract is to render into the terminal's main screen **and scrollback** (`packages/tui/src/tui-main-screen.ts`: writes the full buffer, tracks a viewport top over it, and only clears screen plus scrollback — `\x1b[2J\x1b[H\x1b[3J` — on a width/height change full-redraw). This decision aligns the renderer and terminal seam with pi's `TuiMainScreen` semantics while keeping the recorded Intentional Divergences (Decoded Input Event fork A, Terminal-Owned Image Placement fork B) and the ADR 0035 capability subset unchanged; it records the Termux height-change special-case as not applicable and sets the acceptance criteria for the `/to-spec` → `/to-tickets` → `/implement` series.

## Considered options

- Keep the viewport-clip + in-place-rewrite renderer and add a boot-time screen clear: rejected — the startup header is part of the composed screen and is repainted on every render, so a boot-time clear does not remove it and does nothing for scrollback; it also deviates from pi's first-render "assumes clean screen" semantics.
- Adopt the alt-screen/viewport half (`TuiAltScreen`, layout engine, `ScrollView`) to gain scrolling: rejected — pi gates that half behind the opt-in `uiMode: "fullscreen"`, the ADR 0035 subset has no consumer for it, and alt-screen mode removes the terminal's native scrollback entirely, requiring the Deferred `ViewportTUI` machinery for internal scrolling. The three provider paths run end to end in regular main-screen mode.
- Clear screen + scrollback at boot so the startup banner never appears: rejected — pi's main screen keeps the header/loaded-resources visible until the buffer grows past one screen; the realignment makes it scroll away naturally, which resolves the observed "residual startup info" symptom without an observable deviation.
- Preserve the user's scrollback across a terminal resize: rejected — pi's full-redraw on width/height change emits `\x1b[2J\x1b[H\x1b[3J` (clear screen, home, clear scrollback); matching that is the parity default and the simplest correct reflow.
- Port pi's Termux height-change special-case (skip the full redraw on height change under Termux): rejected as not applicable — C++ targets desktop terminals only, so the environment probe would be dead code on every supported platform. Recorded as not applicable rather than ported.
- Keep images viewport-scoped (removed when their rows leave the visible area): rejected — under scrollback flow an image must follow its content rows so scrolling history keeps the image with its text, matching pi's cell-anchored image behavior expressed through Terminal-Owned Image Placement.

## Consequences

- **The renderer writes the full buffer into the main screen and scrollback.** `Tui::render()` no longer clips to `dimensions.rows`; it writes the full composed buffer with pi's line-flow ordering, tracks a viewport top over the buffer, and positions the hardware cursor relative to that viewport. First render still does not clear (pi "assumes clean screen"): the startup header/loaded-resources block remains visible at boot and scrolls away as the conversation grows.
- **Resize is pi-exact.** Width or height change triggers a full redraw with `\x1b[2J\x1b[H\x1b[3J` — the renderer's full-redraw path and `ProcessTerminal::clear_screen` gain the `\x1b[3J` clear-scrollback so reflow starts clean; the terminal's scroll history is cleared on resize, matching pi.
- **Terminal-Owned Image Placement rows follow content (fork B interplay).** Image sidecars keep their absolute row identity across renders; rows that scroll into the terminal's scrollback carry their image placement, and rows that leave the composed buffer have their placements removed.
- **Scrollback is the history surface.** Terminal scroll-up shows the full session transcript from the composed buffer; the TUI maintains no second virtual history. Session/session-format history surfaces are unaffected — this is a rendering decision only.
- **Synchronized output, clear-on-shrink, render coalescing (16 ms minimum), and `CSI 16 t` consumption stay** as already-aligned renderer behaviors; the differential update strategy changes from in-place row rewrite to pi's line-flow plus first-diff tracking.
- **Evidence regenerates.** `tests/tui/ScreenStateGoldenTest.cpp` gains scrollback-flow scenarios (full-buffer write, viewport-top tracking, resize clear-screen+scrollback, image-follows-content) and regenerates affected screen-state goldens; `tests/coding_agent/tui/InteractiveRenderingGoldenTest.cpp` and the committed `fixtures/pi-coding-agent/e2e/boot.txt`/`turn.txt` goldens are regenerated; the full suite must stay green.
- **Out of scope by explicit agreement.** The recorded renderer-side divergences not implicated by scrollback flow — out-of-band `cursor_location()` vs pi's in-text `CURSOR_MARKER`, caller-set overlay anchors, the tolerant Markdown parser, and the injected `AnimationTimer` — are unchanged and remain recorded; `VirtualTerminal` stays as the deliberate C++-only test double.
- **The Termux special-case is recorded as not applicable** (no probe, no dead branch).
- **Verification is end to end:** automated tests plus one manual real-terminal smoke (scroll-up over a grown transcript, startup header scroll-away, resize behavior) as part of the `/implement` acceptance.
