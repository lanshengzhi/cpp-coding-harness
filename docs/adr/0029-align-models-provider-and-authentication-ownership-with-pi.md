# Align Models, Provider, and authentication ownership with pi

Provider, model, and authentication capabilities are owned exactly where pi owns them at the parity baseline, as a capability subset by omission only. `cch::ai::Models` owns the Provider collection, live model lookup, live authentication operations, request-time authentication resolution, and stream delegation. `cch::coding_agent::ModelRuntime` owns Agent Config Directory paths, `models.json`, built-in/config composition, availability snapshots, Provider recomposition, and `refresh()`, and holds/delegates `Models`. This decision supersedes the host chat-client injection and provider/model precedence ownership recorded in [ADR 0001](0001-centralize-session-assembly-policy.md) and refines the Model contract of [ADR 0019](0019-make-model-and-stream-options-first-class-values.md), per the resolution of parity-map ticket [#326](https://github.com/lanshengzhi/cpp-coding-harness/issues/326).

> Refined by [ADR 0033](0033-own-the-supported-api-adapter-surface-for-the-three-provider-paths.md) (per ticket [#329](https://github.com/lanshengzhi/cpp-coding-harness/issues/329)): the request-option surface below gains `reasoning` (ThinkingLevel), `sessionId`, `cacheRetention`, `timeoutMs`, `maxRetries`, `maxRetryDelayMs` — the set pi's agent harness passes through `streamSimple`; `sessionId` and `cacheRetention` are Supported (not omitted); `serviceTier`, `reasoningSummary`, and `toolChoice` are omitted, not deferred-pending. Transport and `websocketConnectTimeoutMs` remain internal fixed defaults (auto / 15s).

## Considered options

- Keep a catalog-only `Models` with configuration and refresh owned elsewhere piecemeal: rejected because pi's `Models` is a live runtime (lookup, `checkAuth`/`getAuth`, login/logout, stream delegation) and splitting those verbs across modules would substitute non-pi observable semantics.
- Keep `Models` owning `models.json`, snapshots, and refresh directly: rejected because pi assigns configuration policy to the coding-agent layer (`ModelRuntime`), and inverting that direction would block direct Agent Config Directory interoperability.
- Retain the `ProviderRegistry` factory with construction-time API keys and fixed-model clients: rejected because pi Providers are long-lived runtime modules that resolve auth per request; construction-time credentials snapshot secrets and prevent the required precedence behavior.
- Keep `std::optional<Model>` Agent state and pre-transport rejection for setup failures: rejected because pi's `AgentState.model` is required (with an internal `DEFAULT_MODEL`) and its `StreamFn` contract encodes every request/model/runtime failure as a terminal error event plus final Assistant Message; both C++ deviations would add branches pi consumers never see.
- Translate pi mechanically: rejected; C++ keeps idiomatic ownership (`std::shared_ptr`, `util::Expected`, `std::move_only_function`) while observable behavior tracks pi.

## Consequences

- `Model` is a complete passive credential-free value: `id`, `name`, `provider`, `api`, `baseUrl`, `reasoning`, `thinkingLevelMap` (preserving pi's null-vs-missing-key meaning), `input`, `cost`, `contextWindow`, `maxTokens`, static `headers`, and an optional typed per-API `compat` limited to supported APIs. Generic compatibility JSON bags remain prohibited. Every Provider request carries a concrete complete Model; there is no client-construction default-model fallback.
- Agent state holds a concrete Model. When no configured model resolves, an internal `kDefaultModel` mirrors pi's `DEFAULT_MODEL` (`id`/`name`/`provider`/`api` = `"unknown"`, empty endpoint/input, zero capabilities and cost); the Agent adds no special case and streaming fails through normal Provider lookup until a real model is selected.
- `model.provider` selects Provider/authentication identity; `model.api` selects protocol execution inside the composed Provider. The composed DeepSeek Provider retains `provider=deepseek`, resolves DeepSeek auth, and privately delegates `api=openai-responses` to a registered generic adapter. API-adapter registration is private; an adapter's existence does not make a Provider supported.
- Provider is a long-lived runtime module. `ProviderRegistry`, `ProviderFactoryContext`, construction-time API keys, and fixed-model clients are removed. Affected modules are renamed once without compatibility headers or aliases: `ProviderRegistry` → `Models` + `Provider`; `AuthLoader` → `CredentialStore` + coding-agent `AuthStorage`; `ProviderConfigResolution` → `ModelRuntime` + `ModelConfig` + `ProviderComposer`; the high-level `SessionFactory` policy class → `create_agent_session()` plus a private assembly helper.
- Request-level precedence follows pi: supported explicit API key, then stored credential, then ambient auth only when nothing is stored; a stored-credential mismatch or refresh failure never silently falls back. Authentication resolves immediately before each request; OAuth is never snapshotted at Session construction. `checkAuth` is side-effect-free and never refreshes.
- Public trusted `getAuth(providerId)`/`getAuth(model)` follows pi: live resolution performing OAuth refresh and persistence; refresh failure reports the `oauth` category with the stored credential preserved; api-key/store failure reports `auth`; unknown or unconfigured providers resolve empty rather than error. Login is explicit through an injected cancellable `AuthInteraction`. Cached snapshots never replace live `getAuth`/`checkAuth` semantics.
- Stream execution follows pi's `StreamFn` contract: provider lookup, auth, validation, and serialization failures normalize to exactly one terminal error event plus a final Assistant Message returned through the value channel (stop reason `error`); cancellation stays stop reason `aborted`. The `Expected` error alternative is reserved for consumer-sink/infrastructure failure. pi's six Models error categories (`model_source`, `model_validation`, `provider`, `stream`, `auth`, `oauth`) flow through the single `util::Error`/`util::Expected` channel; carrying a category in the terminal payload is a recorded C++ enrichment.
- Request options are the pi subset the three supported paths consume: `temperature`, `maxTokens`, cancellation, explicit `apiKey`, `headers` (pi merge order), `env` (resolution env first, request override), and a post-merge pre-dispatch `transformHeaders` hook stripped before Provider dispatch. `fetch`/`transport`/`onPayload`/`onResponse`/`metadata`/`sessionId` are omitted.
- `models.json` composition follows pi: built-ins, then provider overlay/custom-model upsert (same-ID replaces), then model overrides. A config-only provider id composes from configuration plus privately registered API adapters, so a future restricted configured local Provider is not architecturally blocked; it remains outside the current destination. Invalid config becomes empty user config plus diagnostics; per-Provider composition failure falls back to its built-in or removes it; there is no global rollback.
- High-level SDK injection is a complete `coding_agent::ModelRuntime` held as `std::shared_ptr` in the session options (nullable; default-created from the Agent Config Directory when absent; injected wins over `agentDir` path derivation). Sessions expose it through an accessor; runtimes are reusable across sessions and host `refresh()`/`login()`/`logout()` is live for all holders. The parallel high-level `StreamingChatClient` injection and the default-client `provider_config` branch are removed without a compatibility adapter.
- A runtime and everything it owns (Models, Providers, adapters, transports) is not internally synchronized and carries a single-threaded/executor serialization contract: one runtime may be shared across sessions — and is — but every operation on it (stream, auth, login/logout, refresh) must be driven by the same single-threaded executor or otherwise serialized. `AgentSession::prompt_blocking` runs the prompt on a temporary executor created for that call and must not interleave with another thread driving the same runtime. The Codex WebSocket session cache, the SSE-fallback set, and the Beast WebSocket idle timer all rely on this contract; it is documented on the affected declarations per coding standards §7.5 (ticket #371).
- Trusted in-process authentication may carry `Credential` and short-lived request auth; secrets never enter Model, Session entries/metadata, ordinary frontend status, diagnostics, or logs. Redaction and output bounding are preserved.
- No backward compatibility, migration shims, aliases, or fallback reads are provided for the removed seams; the switch is hard and recorded here.
