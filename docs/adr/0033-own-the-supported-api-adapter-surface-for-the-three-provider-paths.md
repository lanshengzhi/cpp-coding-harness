# Own the supported API-adapter surface for the three provider paths

The original API-adapter surface covered the three provider paths then in scope — `openai-codex-responses` (WS-first), `openai-responses` (DeepSeek custom model), and `anthropic-messages` (the original Kimi path) — as a pi capability subset by omission only. ADR 0059 and issue #763 supersede the Kimi portion: production Kimi now uses the vendor-authoritative `openai-completions` path, while `anthropic-messages` remains for OpenCode Go's Anthropic-family models. No generic OpenAI-compatible substitution, placeholder registry, or compatibility shim is added. This implements parity-map ticket [#329](https://github.com/lanshengzhi/cpp-coding-harness/issues/329), refining the request-option seam frozen by [#326](https://github.com/lanshengzhi/cpp-coding-harness/issues/326) and the Codex transport consequences of [#328](https://github.com/lanshengzhi/cpp-coding-harness/issues/328). The completion gate, fixture strategy, and downstream handoff that make this surface verifiable are recorded in the [#330](https://github.com/lanshengzhi/cpp-coding-harness/issues/330) resolution.

## Considered options

- Adopt one generic OpenAI-compatible adapter for all providers: rejected because it substitutes observable semantics — Codex is an OAuth-only WebSocket-first Responses path rooted at `https://chatgpt.com/backend-api`, while Kimi's vendor contract and OpenCode Go's Anthropic-family models each have distinct protocol/catalog requirements.
- Codex SSE-only transport: rejected because pi's Codex transport is WebSocket-first with a narrowly defined SSE fallback; socket reuse and `previous_response_id` continuation are part of the observable contract.
- Keep an `OpenAIResponsesCompat` typed struct: rejected as a placeholder surface — all seven pi fields are fixed at frozen defaults or auto-detection for the scoped paths, and the two Codex catalog flags are inert without producers.
- Port zstd SSE decompression as a requirement: rejected as out of scope — pi itself runs a plain-JSON branch when Node zstd is unavailable; omitting it is a permitted subset, not a divergence.
- Expose raw per-API option structs (`OpenAIResponsesOptions`, `AnthropicOptions`): rejected because adapters stay private behind `stream`/`streamSimple`; the request-option surface is the flat set the scoped harness consumer passes.
- Keep `models.json` `compat` overrides (the graduation #326 reserved): rejected — no scoped consumer reaches them; the C++ config schema has no compat surface at all.

## Consequences

- **Supported/Deferred criterion:** Supported = semantics exercised end-to-end by a scoped path (a scoped built-in catalog/model value that changes wire behavior, or a scoped consumer that can reach it). Deferred = reachable only through unscoped producers (extension hooks, grammar-constrained tools, `addedToolNames`, models.json compat overrides) — deleted from the surface entirely, with adapter behavior fixed at pi's frozen defaults. A catalog flag with no scoped producer (Codex `supportsOpenAIGrammarTools`/`supportsToolSearch`) is Deferred. **#878 amendment (2026-10-07, authorized by the spec #865 flow):** re-measured against codemode as landed (#870 declarations, #874 sandboxed execution, #877 presentation), neither flag gained a scoped producer, so both stay Deferred — the itemized measurement is in the [amendment section](#amendment--grammar-chain-and-tool-search-stay-deferred-878-spec-865) below.
- **Exactly four adapters** exist in C++: `openai-codex-responses`, `openai-responses`, `openai-completions` (plus a shared conversion/usage layer), and `anthropic-messages`. Every other pi adapter is absent with no registry placeholder; registration stays private per #326.
- **Built-in catalogs** use the pinned upstream artifacts where they are authoritative and the vendor specification for Kimi: Codex 6 models, Kimi 4 models (`k3`, `k3-256k`, `kimi-for-coding`, `kimi-for-coding-highspeed`; text+image, API-key-only, with vendor context/cost/token/thinking values), and the remaining provider catalogs from the verified snapshot. DeepSeek still supports the models.json custom-model upsert (same-ID replace).
- **Codex transport is WebSocket-first, fully aligned:** `auto` tries WebSocket, pre-start failure records a diagnostic and falls back, post-first-event failure surfaces without fallback, protocol/API errors never fall back; session/account-keyed socket reuse (5-minute idle close, 55-minute hard age), `previous_response_id` continuation with input delta while retaining `store:false`, one WS retry each for `previous_response_not_found` and pre-start `websocket_connection_limit_reached`, per-session SSE-only marking after WS failure. zstd SSE compression is omitted via pi's own plain-JSON branch.
- **Request-option surface (amends #326/ADR 0029):** the #326 seven (`temperature`, `maxTokens`, cancellation, explicit `apiKey`, `headers`, `env`, `transformHeaders`) plus `reasoning` (ThinkingLevel), `sessionId`, `cacheRetention`, `timeoutMs`, `maxRetries`, `maxRetryDelayMs` — exactly the set pi's agent harness passes through `streamSimple`. `sessionId` drives Codex `prompt_cache_key`/`session-id`/`x-client-request-id` and DeepSeek session-affinity headers (silently ignored by DeepSeek per its documented contract); `cacheRetention` defaults `"short"`, compaction passes `"none"`, `PI_CACHE_RETENTION=long` via env. Omitted with no placeholder: `serviceTier` (usage multiplier unreachable), `reasoningSummary` (fixed `"auto"`), `toolChoice` (fixed `"auto"`), `metadata`, `onPayload`/`onResponse`, `thinkingBudgets`, `transport`, `websocketConnectTimeoutMs` (internal defaults fixed: auto / 15s). Raw per-api option structs do not exist.
- **Typed compat, final:** C++ `AnthropicMessagesCompat` = exactly `{ forceAdaptiveThinking, allowEmptySignature }` for the remaining OpenCode Go Anthropic-family models. `OpenAIResponsesCompat` does not exist; all seven pi fields are fixed at frozen defaults/auto-detection. Deferred machinery: grammar emission, tool search/`splitDeferredTools`/`addedToolNames` replay, the Claude subscription branch, budget-based thinking where no shipped model reaches it, strict-mode overrides, and session-affinity format overrides. **#878 amendment (2026-10-07, authorized by the spec #865 flow):** grammar emission and the tool search/`addedToolNames` replay were re-measured against codemode as landed and stay Deferred, each with a named measured reason — see the [amendment section](#amendment--grammar-chain-and-tool-search-stay-deferred-878-spec-865) below.
- **Message/history conversion fully aligned:** system prompt extraction per path (Codex `instructions` with default; DeepSeek developer role for reasoning models; Anthropic system), surrogate sanitization, tool-result grouping with `is_error`, tool-call id normalization (`[A-Za-z0-9_-]`, 64 chars), image blocks in both adapters, thinking/redacted-thinking replay with empty-signature preservation via `allowEmptySignature`, Codex `include:["reasoning.encrypted_content"]` with encrypted items replayed as signatures, text signature v1 (item-id/phase), stateless full-context replay for DeepSeek (no `previous_response_id`).
- **Usage/cost normalization fully aligned:** Responses cached/cache-write subtraction with output/reasoning/totals; Anthropic `message_start`/`message_delta` partial-field updates with optional thinking-token detail and total = input + output + cache-read + cache-write; DeepSeek uncached-input + `cached_tokens` split and `reasoning_tokens`; shared `calculateCost` with cost tiers and the Anthropic 1h cache-write 2× rule. Service-tier multipliers omitted.
- **Termination, retries, cancellation:** terminal mapping per adapter (Responses `completed`/`done` → `stop`, `incomplete` → `length`, tool call → `toolUse`, `failed`/missing terminal → error, no `[DONE]` for DeepSeek; Anthropic `end_turn|pause_turn|stop_sequence` → `stop`, `max_tokens` → `length`, `tool_use` → `toolUse`, `refusal|sensitive` → error, unknown stop reasons throw, missing `message_stop` → terminal error carrying the partial message). Anthropic malformed-event JSON repair, incremental tool-argument repair parsing, unknown SSE events ignored, SSE `error` event throws its data, scratch buffers removed on every error. Retries zero by default; configured retries cover network errors and transient 429/5xx, exclude terminal quota/billing errors, exponential 1s base or Retry-After bounded by 60s default; `timeoutMs` bounds SSE response headers, WS uses idle timeout, WS connect default 15s. Cancellation propagates to fetch/reader/socket and yields exactly one `aborted` terminal event ("Request was aborted"), per #326's terminal-error-event contract.
- **`streamSimple` pipeline fully aligned:** `getSupportedThinkingLevels`/`clampThinkingLevel` (null = unsupported, xhigh/max require explicit mapping, requested level clamped); Responses effort mapping through `thinkingLevelMap` (DeepSeek `high`/`max`, Codex incl. `xhigh`); Kimi uses the vendor `openai-completions` catalog and omits effort for its highspeed/no-knob model; Anthropic adaptive branch (`thinking:{type:"adaptive",display:"summarized"}`, `output_config.effort`, temperature omitted while thinking enabled); `clampMaxTokensToContext` (contextWindow − estimated − 4096 safety); `assertRequestAuth` requires the active API-key or OAuth resolution. The budget branch is skipped for adaptive models and omitted.
- models.json `compat` overrides remain omitted: the C++ config schema has no compat surface at all.

## Amendment — grammar chain and tool search stay Deferred (#878, spec #865)

Issue [#878](https://github.com/lanshengzhi/cpp-coding-harness/issues/878) asked which grammar-chain and
tool-search semantics codemode, **as landed**, actually requires, so the rows this slice reaches could be
flipped. The measurement below answers that. It was taken at Pike `d47c68e11` against
`../pi` `7c10bd43` (`v1.0.4`), and it is a **recorded observation**, not a design option: the fork
between "enable the minimal surface" and "record that there is none" was settled by reading the
landed producers (ADR 0066 product principle; validation.md §Acceptance discipline 3).

**Outcome: the minimal surface codemode as landed requires is empty. Nothing is enabled by this
slice, and nothing below flips out of Deferred.** Each item is named individually, as the ticket
requires — there is no blanket flip in either direction.

| Capability (stays Deferred) | Measured reason: no producer in Pike's codemode path |
|---|---|
| Grammar-constrained tool input (`Tool.constrainedSampling` type `grammar`) | Upstream's only grammar declaration on the codemode path is on the **model-facing** `codemode` tool's `code` argument — `packages/coding-agent/src/extensions/codemode/tool.ts` at `7c10bd43`: `constrainedSampling: { type: "grammar", variants: { openai_lark: CODEMODE_SOURCE_GRAMMAR } }` (grammar defined in `packages/codemode/src/source.ts`). Pike has no model-facing script tool: a declaration is `<workspace>/.pi/codemode/<tool>.json` naming a fixed `source` `*.js` file (the recorded #870 intentional divergence), and the model supplies the declared tool's ordinary JSON-Schema `parameters`. No Pike Tool carries a grammar at all — `cch::ai::Tool` is `{name, description, parameters}`. |
| Grammar emission in the adapters (`resolveGrammarConstrainedSampling`, `createGrammarToolInputProperties`, the Responses `custom` tool with `format: {type:"grammar"}`, and the raw-text `custom_tool_call` input folded back into the single required string property) | No reachable input: with no Tool declaring a grammar, the emission path has nothing to emit. The Responses/Codex tool conversion emits function tools only (`src/ai/api/ResponsesPayload.cpp` `responses_tools`). |
| `supportsOpenAIGrammarTools` catalog flag (Codex / OpenAI-Responses compat) | Nothing in Pike consumes the flag. It would gate the emission path above, which has no input. |
| `supportsToolSearch` catalog flag, and the tool-search replay named `splitDeferredTools` at this ADR's baseline (`resolveTranscriptTools` at `7c10bd43`) | Nothing in Pike consumes the flag, and the replay it selects over has no input — see the `addedToolNames` row. |
| `addedToolNames` replay (`SystemMessage.toolsAdded` rendered as `additional_tools`, or as a `tool_search_call` + `tool_search_output` pair) | Pike produces `tools_added` only on the **initial** System Message (the four fixed built-ins) and reads it back on resume to re-select the active set (`src/coding_agent/AgentSessionExecution.cpp`). The request's tool list is the Agent's active registry (`context.tools`), which already contains every extension/MCP/codemode tool because they are registered before the registry moves into the Agent. There is no mid-conversation tool activation whose in-place addition would need replaying. |

**No decider is asserted beyond the flow.** This amendment is an owner decision recorded through the
repository's explicitly authorized spec flow of [#865](https://github.com/lanshengzhi/cpp-coding-harness/issues/865)
(2026-10-07), in the same attributed manner as the #869/#870/#873/#874/#875/#876 rulings in
[ADR 0066](0066-pi-capability-scope-decisions-and-open-questions.md). It rules on no other capability: the
remaining Deferred machinery in this ADR's Typed-compat row is untouched, and the `packages/codemode`
"Script→session-tool routing" row in ADR 0066 likewise stays undecided.

**If grammar emission ever becomes genuinely reachable** — a model-facing script tool, or a declared tool
that carries a grammar — that is new evidence and starts a new ticket from these rows; it is not a silent
flip of them. The owner ruling for this slice explicitly declined to invent a producer for it
(A Pike-only per-declaration grammar field or a model-facing `codemode` tool is a product divergence this
spec does not authorize).
