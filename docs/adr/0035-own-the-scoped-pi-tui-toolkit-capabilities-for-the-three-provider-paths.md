# Own the scoped pi-tui toolkit capabilities for the three provider paths

The pi-tui toolkit surface is exactly the reusable terminal/input/editor/component capabilities the three scoped provider paths exercise through pi's default interactive boot — the regular main-screen mode — as a pi capability subset by omission only: the entire opt-in alt-screen/viewport half, extension-only seams, platform-native helpers pi itself fails closed without, JS-runtime re-exports, and diagnostic surfaces are Deferred with no placeholder surface. This implements parity-map ticket [#333](https://github.com/lanshengzhi/cpp-coding-harness/issues/333), consuming the capability inventory and 58-row delta from [#332](https://github.com/lanshengzhi/cpp-coding-harness/issues/332) and bounded by the OAuth presentation contract frozen in [#328](https://github.com/lanshengzhi/cpp-coding-harness/issues/328) and the pi-agent-core terminal-event/error surface frozen in [#331](https://github.com/lanshengzhi/cpp-coding-harness/issues/331). The strict-alignment directive applies: names, namespaces, and layout may change to match pi; there is no backward-compatibility burden. The completion gate, fixture strategy, and downstream handoff that make this surface verifiable are recorded in the [#334](https://github.com/lanshengzhi/cpp-coding-harness/issues/334) resolution.

## Considered options

- Adopt pi's raw-string key matching end to end (`matchesKey(data, keyId)` on raw escape sequences, process-global Kitty flag): rejected — decoding once at the terminal edge into typed `KeyEvent`/`PasteEvent` values is the repository's passive-value idiom, gives a single coverage/audit point for pi's sequence tables, and carries the bounded-paste hardening; the observable contract (which sequences produce which actions, the `modifier+key` identifier grammar, Kitty press/repeat/release semantics) is fully preserved and is what the gate must prove. Adopting string matching across consumers would be mechanical TypeScript translation, which the map excludes.
- Serialize Kitty/iTerm2 protocol bytes into render lines like pi: rejected — protocol-neutral image sidecars with terminal-owned absolute placement (`place_image`/`remove_image`) keep protocol bytes out of component output, make the `VirtualTerminal` evidence harness protocol-aware, and preserve the observable contract (which image lands in which cell region, with which sizing math, protocol selection, animation-id reuse, and fallback text). pi's line-bookkeeping helpers (`isImageLine`, metadata registry, `cropKittyImageLine`) exist only to manage sequences-in-lines and have nothing to port.
- Claim the alt-screen/viewport half (`TuiAltScreen`, layout engine, `ScrollView`, stacks, mouse/selection/scrollbars, OSC 133 navigation, flash messages): rejected — pi gates all of it behind the opt-in `uiMode: "fullscreen"` setting/`--ui-mode`/`--fullscreen` flags while the default interactive boot is the regular main-screen mode; the #327 settings field subset contains no `uiMode` and the #327 CLI surface contains no UI-mode flag, so no scoped consumer can reach it. The three paths run end to end in regular mode.
- Adopt pi's mutable process-global `KeybindingsManager` (`getKeybindings`/`setKeybindings`): rejected as API shape — the observable contract (pi's default table, one startup `keybindings.json` read with replace-all-defaults/unbind/conflict diagnostics, caller-scoped registries such as pi's session-selector local manager) is already expressed by the resolved immutable `KeybindingRegistry`; a mutable global would regress determinism without changing any observable behavior.
- Keep the synchronous autocomplete provider seam: rejected — pi wires the async, debounced, abortable `CombinedAutocompleteProvider` (slash commands plus `@`/`#` fd-backed file completion) into the editor unconditionally at interactive startup; a synchronous seam cannot express debounce, abort, or filesystem completion without substituting observable UX.
- Keep the editor without history: rejected — pi calls `addToHistory` on every submit path and recalls entries on cursor-boundary up/down; prompt recall is exercised in the normal interactive flow of all three paths.
- Defer the single-line `Input` component: rejected — the #328 login presentation (Codex manual-code entry raced against the browser callback) and the selector search inputs consume it; building it from the editor primitives mirrors pi's own composition.
- Export the reusable editor primitives (`UndoStack`, `KillRing`, word navigation, `wordWrapLine`) as public seams: rejected — pi itself keeps them out of the package surface (`index.ts` does not re-export them); visibility is not an observable contract, and the C++ `Input` reuses them internally exactly as pi's does.
- Port the `Marked`/`Token`/`Tokens` re-export: rejected — a TypeScript parser instance is not consumable by C++ hosts; the C++ Markdown parser remains the divergence carrier with rendered output as the parity surface.
- Keep `TruncatedText`'s `"..."` default: rejected — pi's `TruncatedText` hard-cuts with no ellipsis; the strict-alignment directive removes the divergent default (no scoped consumer sets one).
- Port Apple-Terminal Shift+Enter synthesis and the darwin native-modifier prebuild: rejected as a permitted subset — pi fails closed to `false` when `darwin-modifiers.node` is unavailable, so omission reproduces one of pi's own shipping behaviors (precedent: zstd SSE omission in ADR 0033); newline entry remains available through the full `tui.input.newLine` binding set (`shift+enter`, `ctrl+j`).
- Keep `EditorOptions::disable_submit`: rejected — it has no consumer and no pi analog (pi's editor always submits; busy-submit routing is app-layer admission policy); removed as dead surface under the strict-alignment directive.

## Consequences

- **Terminal seam is Supported and aligned.** `Terminal`/`ProcessTerminal` keep the C++ absolute-cursor, `Expected`-carrying, capability/mode-reporting shape with caller-supplied fds and the serial worker. Aligned additions the interactive boot exercises: `set_title` (OSC 0), `set_progress` (OSC 9;4 with pi's 1-second keepalive), and `drain_input` (pre-exit drain of Kitty key-release leakage). Raw mode, bracketed paste (`?2004`), SIGWINCH refresh, Kitty negotiation (flags 7 = disambiguate|events|alternate-keys) with modifyOtherKeys fallback, and split-response buffering with pi's 150 ms fragment timeout are already aligned and stay.
- **The input protocol layer is Supported under the recorded decoded-event divergence (fork A).** Typed `KeyEvent`/`PasteEvent` decode at the terminal edge with pi's full sequence-table coverage (legacy, xterm modifyOtherKeys `CSI 27;mod;key~`, Kitty CSI-u with event types, shifted/base-layout alternate keys, lock-mask filtering, non-Latin layout safeguards); `parse_key_id`/`key_id`/`matches_key` implement pi's `modifier+key` identifier grammar including alias canonicalization; press/repeat/release with per-component release opt-in (`accepts_key_releases` ↔ pi `wantsKeyRelease`); the bounded paste (`kMaxPasteBytes` = 1 MiB) is retained as C++ hardening; the per-terminal `KeyboardProtocol` capability replaces pi's process-global Kitty flag (observably equivalent in the single-terminal product). The `StdinBuffer`-equivalent decoder (CSI/OSC/DCS/APC/SS3 completeness, old-style and SGR mouse, flush timeout) stays private — pi exports `StdinBuffer` but no scoped consumer imports it.
- **Keybindings are Supported and re-pinned to `83114817`.** The 30 assembled `tui.*` actions match pi's frozen table exactly (21 `tui.editor.*`, 3 `tui.input.*`, 6 `tui.select.*`) with pi's default keys; the `keybindings.json` contract per `docs/keybindings.md` (one startup read, replace-all-defaults, empty-array unbind, bounded redacted diagnostics, immutable resolved registry consumed by dispatch/help/hints alike) is unchanged. `tui.input.copy` and the six `tui.altScreen.*` IDs remain recognized-but-unbound: their only active behavior is alt-screen selection copy, so they defer with the alt-screen half and are diagnosed as known-but-unassembled, never no-op bindings. The editor's pi-aligned bubble behavior (a copy-mapped key passes through to app-layer dispatch) holds without the action existing.
- **The editor stack is Supported with two new alignments.** Multiline grapheme-segmented editing, paste-marker-aware word wrap, paste markers with `expanded_text`, undo, kill ring (yank/yank-pop), word navigation, jump-to-char, keybinding-table dispatch, and cursor-location reporting are already aligned. New: **history** (`addToHistory` plus cursor-boundary up/down recall, matching pi's submit-path calls) and **async debounced abortable autocomplete** (trigger characters, `force`, cancellation, and `applyCompletion` text surgery replacing the prefix-echo seam), expressed with `std::move_only_function` sinks and token/generation cancellation per the event-guardrail rather than promises. Editor chrome aligns to pi: visible-line window sized `max(5, floor(rows × 0.3))` with scroll-border indicators, `paddingX`, `autocompleteMaxVisible` (default 5, clamped 3..20). `EditorOptions::disable_submit` is removed as dead surface. The reusable primitives (undo stack, kill ring, word navigation, wrap) stay private, matching pi's package surface.
- **Autocomplete is Supported:** the async `AutocompleteProvider` contract, the `AutocompleteItem`/`AutocompleteSuggestions`/`SlashCommand` values, and `CombinedAutocompleteProvider` semantics — slash-command completion plus `@`/`#` filesystem completion with quoted-path handling, `fd`-spawn directory walking (graceful absence yields empty file suggestions, exactly pi's `fdPath: null` branch), `.git` exclusion, fuzzy ranking, and abort awareness.
- **Fuzzy matching is Supported as a public reusable module** (subsequence scoring with consecutive/word-boundary bonuses and matched-index reporting, ranking filter) promoted from the `SettingsList`-internal helper; the pi-coding-agent selectors consume it (pi: 4 files).
- **The single-line `Input` component is Supported** (horizontal scrolling, bracketed paste, kill ring, undo, word navigation, submit/escape sinks) and takes the pi-canonical header name: the key/paste **event** header `include/cch/tui/Input.hpp` renames to `Keys.hpp` (pi `keys.ts`), and the component claims `Input.hpp` (pi `components/input.ts`). Autocomplete values move from `Editor.hpp` to `Autocomplete.hpp` (pi `autocomplete.ts`); fuzzy claims `Fuzzy.hpp`; the width/wrap/truncate utility subset claims a public header (pi `utils.ts` public subset).
- **The TUI core is Supported.** `Component` (`render → Expected<RenderResult>`), `Container`, and `Focusable` with the out-of-band `cursor_location()` query (recorded divergence from pi's in-text `CURSOR_MARKER`; the IME hardware-cursor outcome is identical) stay. The owned `Overlay` model stays (recorded divergence from pi's any-component overlays with handles), with observable alignment on the nine anchors, percentage sizing, margins/offsets, stacking order, and the eligible/blocked/resume focus-restore policy. The main-screen differential renderer keeps line-diff updates with hardware-cursor positioning (pi default: hidden unless enabled), clear-on-shrink semantics, render coalescing aligned to pi's 16 ms minimum interval, and `CSI 16 t` cell-size consumption.
- **Terminal image is Supported under the recorded sidecar divergence (fork B).** Capability detection (per-emulator env rules with the tmux probe), Kitty/iTerm2 encoding behind terminal-owned `place_image`/`remove_image`, PNG/JPEG/GIF/WebP dimension sniffing, cell-size math (9×18 px default, `CSI 16 t` updates), resource-id/revision reuse for animation, a public OSC 8 `hyperlink` helper, and pi-exact fallback text (`[Image: path [mime] WxH]` with `~/` shortening and `file://` linking). pi's in-line image bookkeeping has no analog and nothing to port; placement outcomes are the parity surface.
- **The text/width utility subset is Supported as public surface:** `visible_width`/wrap/truncate/slice/strip equivalents of pi's `visibleWidth`, `wrapTextWithAnsi`, `truncateToWidth`, `sliceByColumn`, `stripTerminalSequences`, promoted from the private `UnicodeWidth` detail header. `getOsc8LinkAtColumn` is Deferred (its only consumer is alt-screen link clicking).
- **The component set is Supported:** `Box`, `Text`, `Spacer`, `SelectList` (with layout options and theme hooks), `SettingsList` (search rebuilt on the `Input`/`fuzzy` seams at implementation), `Markdown` (C++ tolerant parser retained as a recorded divergence; streamed-fence trimming, strict-strikethrough, code-block border/indent, and capability-aware link rendering are the observable parity surface), `Image`, `Loader` (injected `AnimationTimer` retained as a recorded divergence from pi's self-animating `setInterval`; 80 ms braille semantics unchanged), `CancellableLoader` (Escape via `tui.select.cancel` aborts; the explicit state enum and completion/cancellation sinks stay), and `TruncatedText` with pi's hard-cut default (the `"..."` default is removed under strict alignment).
- **`VirtualTerminal` is retained** as a deliberate C++-only idiom (public protocol-aware test double; pi's equivalent is test-local) and serves as the gate's rendering-evidence harness. The bounded `PasteEvent`, platform-aware keybinding resolution with structured issues, and `ViewportAware` likewise stay as recorded C++ idioms.
- **Deferred with no placeholder surface:** the entire alt-screen/viewport half (`TuiAltScreen`/`ViewportTUI`/`setLayoutRoot`, the layout engine and `LAYOUT_NODE` protocol, `ScrollView`, `Stack`/`HStack`/`VStack`, SGR mouse/wheel/scrollbar interaction, app-owned text selection with auto-scroll, OSC 8 click-through, OSC 133 prompt navigation, `AltScreenFlashContainer`, the six `tui.altScreen.*` actions and `tui.input.copy`'s active behavior — no `uiMode` setting, no UI-mode CLI flag, no bindings, no layout seams); the `EditorComponent` extension interface (extension-supplied editors are extension fog); the TUI extension input-listener chain (`addInputListener` consume/rewrite — its only consumer is extension terminal input); Apple-Terminal Shift+Enter synthesis and darwin native-modifier polling (permitted subset); the Windows VT-input native helper (Windows is not a supported TUI platform per ADR 0025); live `?2031` color-scheme notifications and the TUI-level background/scheme query APIs (their only consumer is auto-theme sync, which is not assembled; startup OSC 11/`?997` detection remains Supported); the `Marked` re-export; and the diagnostic surface (`onDebug` Shift+Ctrl+D dump, `fullRedraws`, `PI_TUI_WRITE_LOG`) plus pi exports with no scoped consumer (public `StdinBuffer`, terminal-colors parsers, the keyboard-negotiation parser).
- **Baseline pins advance to `83114817`** across the toolkit: `include/cch/tui/Keybindings.hpp` and `src/tui/Keybindings.cpp`, the behavioral-baseline comments in `src/tui/` (re-verified file by file at implementation), and `docs/keybindings.md`. ADR 0026/0028's User Bash pins and the `src/coding_agent/tui/` baseline comments are app-layer surface and are **not** advanced by this decision; their re-verification belongs to the pi-coding-agent phase audit.
- **Consumption constraints are honored:** the #328 login presentation (LoginDialog/OAuthSelector equivalents, manual-code race, cancellation UX) consumes `Input`, `SelectList`, overlays, `Loader`/`CancellableLoader`, fuzzy, and `Text`/`Markdown` — all Supported; the #331 terminal-event/error surface renders through the same component set; E2E verification remains deferred to the pi-coding-agent gate.
- **Evidence obligations pass to #334:** the two forks carry explicit parity-evidence duties — input-decoding differential fixtures (sequence → decoded event → action across legacy/modifyOtherKeys/Kitty tables) and `VirtualTerminal` rendering goldens (differential frames, overlay compositing, image placement/fallback) — captured from frozen pi tests at `83114817`.
