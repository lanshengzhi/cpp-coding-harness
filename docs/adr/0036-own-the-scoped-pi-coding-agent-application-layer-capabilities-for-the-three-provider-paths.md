# Own the scoped pi-coding-agent application-layer capabilities for the three provider paths

The pi-coding-agent phase aligns the C++ application layer to pi's `packages/coding-agent` at frozen baseline `83114817c68f5413e4d7ba6d7003ddc511cd31d2` as a **strict subset by omission only**: no C++-only product surface survives, every inconsistency is deleted rather than recorded as an Intentional Divergence, and there is no backward-compatibility burden. The phase's decisions are the G1–G6 grilling records ([#389](https://github.com/lanshengzhi/cpp-coding-harness/issues/389) CLI assembly, [#390](https://github.com/lanshengzhi/cpp-coding-harness/issues/390) interactive components, [#391](https://github.com/lanshengzhi/cpp-coding-harness/issues/391) configuration/resume/session behaviors, [#392](https://github.com/lanshengzhi/cpp-coding-harness/issues/392) system prompt/slash commands/skills/prompt templates, [#393](https://github.com/lanshengzhi/cpp-coding-harness/issues/393) theme, [#394](https://github.com/lanshengzhi/cpp-coding-harness/issues/394) completion gate and handoff), consumed from the R1/R2 research ([#387](https://github.com/lanshengzhi/cpp-coding-harness/issues/387), [#388](https://github.com/lanshengzhi/cpp-coding-harness/issues/388)) and bounded by the pi-ai/pi-agent-core/pi-tui contracts frozen in ADR 0029–0035. This ADR is the phase documentation pass (map ticket [T1, #395](https://github.com/lanshengzhi/cpp-coding-harness/issues/395)): it records the G1–G6 decisions, the app-layer baseline re-verification against `83114817` (ADR 0035's obligation), and the downstream facts the spec and gate depend on.

## Considered options

- Record the C++-only surface as Intentional Divergences and keep it: rejected by the charted HITL ruling (2026-08-06) — the phase aligns as a strict subset; every inconsistency is deleted, never recorded as a divergence, with no compatibility burden.
- Align module-by-module without a phase documentation pass: rejected — ADR 0035 explicitly deferred the app-layer baseline pins (`src/coding_agent/tui/` comments, ADR 0026/0028 User Bash pins) to this phase's audit, and the phase's decisions must be recorded in one place before `/to-spec` consumes them.
- Keep the README/CONTEXT.md describing the pre-phase surface and let implementation rewrite them: rejected — the docs pass is a phase deliverable (G1–G6 handoffs all name it), so the README's app-layer sections are brought to the decided surface here, with ADR 0036 as the authority for what lands at implementation.

## Decisions (the phase surface)

**G1 — CLI assembly and flag surface ([#389](https://github.com/lanshengzhi/cpp-coding-harness/issues/389)).** The CLI entry chain aligns to pi `cli.ts` → `main.ts`: the full pi `args.ts` flag inventory is classified Supported/Deferred-with-no-placeholder/Deleted; `--provider`/`--model`/`--models`/`--api-key` (frozen #327), `--thinking` (7 levels, #331), `--help`/`--version` (`--version` new, prints the C++ binary's own version), `--print`/`-p`, `--mode text` (pi-default spelling), the session-family flags (surface; behavior → G3), `--approve`/`-a`/`--no-approve`/`-na` (both kept with pi's trust-override semantics — pi has both), `--no-skills`/`--no-prompt-templates`/`--prompt-template` (machinery → G4), `--list-models [search]`, positional + `@file` args. Deferred with no surface: `--no-tools`/`--no-builtin-tools`/`--tools`/`--exclude-tools`, `--export`, `--extension`/`--no-extensions`, `--offline`, `--ui-mode`/`--alt`, `--verbose`, extension-contributed flags. Deleted (C++-only): `--fake`, `--enable-bash`, `--max-turns`, `--workspace` with all their plumbing; the workspace boundary survives as the internal containment seam `workspace := cwd`. `--mode json` and `--mode rpc` are **rejected with an explicit error**; the `Frontend` enum shrinks to {Print, Interactive} with pi's vocabulary. Print mode aligns to pi `runPrintMode`: final assistant text blocks only (the C++ event-streaming `TextCliRenderer` is deleted), terminal outcomes → stderr + exit 1, pi merge order for stdin/`@file`/positionals (no separator, no prompt-required guard), one-shot slash dispatch deleted, exit codes unify to pi (usage errors → 1), SIGTERM/SIGHUP → dispose + 143/129. Stdout takeover is Deferred with no surface.

**G2 — interactive-mode application components ([#390](https://github.com/lanshengzhi/cpp-coding-harness/issues/390)).** All 40 pi components classified; the message/execution pipeline (`assistant-message`, `user-message`, `tool-execution` + `diff`, `bash-execution` + `visual-truncate`, `compaction-summary-message`, `skill-invocation-message`, `branch-summary-message`/`custom-message` rendering only, `dynamic-border`), login/auth (`login-dialog`, `oauth-selector`, the generic string-list selector for auth-type/`select` prompts — pi's `extension-selector.ts` is not extension-only), trust (`trust-selector`, boot trust prompt as a main-TUI overlay — recorded presentation divergence), footer/status (`footer` minus extension/xp lines, `status-indicator`, `countdown-timer`, `keybinding-hints`), selectors (`model-selector` + `model-search`, `scoped-models-selector`, `settings-selector` over the #327 subset + the graduated `hideThinkingBlock`/`outputPad`, `session-selector` + search, `tree-selector` with the tree-navigation runtime capability graduating from fog, `user-message-selector`), and editor chrome (custom-editor routing, OSC 133 A/B/C zones, `app.message.copy`, `app.suspend`, external editor env-only) are Supported; `markdown-transform`, `thinking-selector`, `theme-selector`, `show-images-selector`, extension editor/input, `config-selector`, `first-time-setup`, `bordered-loader`, the easter eggs, `index.ts`, and `ui.onDebug` are Deferred with no placeholder. **R1 correction:** the app `*` catalog at `83114817` has **42 actions** (`core/keybindings.ts:13-54`), not 43; the C++ app layer adopts pi's full 42-action `AppKeybindings` table and the own `KeybindingCatalog` seam is deleted, with the assembled main-editor subset (15 actions) and selector-scoped bindings as listed in the record.

**G3 — configuration, resume, session picker, switching ([#391](https://github.com/lanshengzhi/cpp-coding-harness/issues/391)).** The `--resume` picker (and boot missing-cwd prompt) get a minimal pi-shaped startup-TUI host; in-session `switchSession`/`newSession`/`fork` are Supported with pi's verbatim flows; `--list-models` is pi's exact 6-column table with fuzzy `[search]`; session-family CLI semantics are pi's (`--session` open-or-create-at-path with ID exact→prefix local→global resolution and the cross-project fork prompt; `--resume` picker; `--continue` most-recent; `--fork` conflicts + local-only target check; `--session-id` validation/conflicts/warning-create; `--no-session` silent short-circuit — C++-today conflict errors deleted; `--name` non-empty guard; custom `--session-dir` cwd-filter semantics pinned); runtime `setModel`/`cycleModel` with pi's auth guard, `model_change` entry, settings-default update, and thinking re-clamp; the persisted-session resume chain (CLI model → leaf-path model + auth → settings default → provider default → first available) with the `Could not restore model <p>/<m>` warning and the pinned fact that pi prints no "Restored model:" at this baseline; missing-cwd recovery verbatim; ten pinned source facts recorded for the spec.

**G4 — system prompt, slash commands, skills, prompt templates ([#392](https://github.com/lanshengzhi/cpp-coding-harness/issues/392)).** The session System Prompt is built in pi's exact shape at session construction and on `/reload` (default/custom branches, tool snippets + guidelines with the four fixed tools' verbatim `promptSnippet`/`promptGuidelines`, `<project_context>`, skills section, cwd line) with the C++ binary's own ("pike") identity — the delta confined to identity lines and pinned by a differential golden; the `transform_context` skills injection and `prompt::PromptProcessor` are deleted. Project Context Files (global + cwd ancestor chain, linked-worktree shadowing) are Supported and **not** Project Trust gated; SYSTEM.md/APPEND_SYSTEM.md + `--system-prompt`/`--append-system-prompt` per pi. The legacy `CommandRegistry`/`CommandEffect`/`CommandContext` seam remains deleted. For the Native TUI, issue #502 adds `SlashCommandRouter` (ADR 0043) over pi's 17-entry autocomplete catalog plus `/clear`, `/help`, and their aliases; the router owns parsing, alias resolution, argument validation, unknown-command classification, and immediate-command execution through a rendering-free host context, while `InteractiveMode` owns modal and presentation effects. `/export` `/import` `/share` `/changelog` `/debug`, the easter eggs, and `/clone` (user ruling) remain Deferred; unknown slash text produces a user-visible routing error unless the host explicitly preserves a registered dynamic resource or compatible absolute-path submission. `enableSkillCommands` graduates into the settings subset. Skill discovery aligns (user `~/.pi/agent/skills` in pi mode, project `.pi/skills` trust-gated, CLI `--skill`, `--no-skills` drops discovery but keeps explicit paths, `.agents/skills` convention Supported with its own baseDir), `Skill` loses the preloaded content (read at invocation), prompt templates align with `.pi/prompts` sources, and the loader is re-expressed as the pi `DefaultResourceLoader` subset: project markers move `.cpp-harness/` → `.pi/`, the `ResourceEnablement` policy and extensions/packages markers are deleted, diagnostics take pi's `ResourceDiagnostic` shape. The loaded-resources presentation (Context/Skills/Prompts sections, scope grouping, `app.tools.expand` notice) is Supported; no Extensions section.

**G5 — theme controller and theme assets ([#393](https://github.com/lanshengzhi/cpp-coding-harness/issues/393)).** The theme asset format is pi's exactly (optional `$schema`, required `name`, optional `vars` with recursive resolution + circular-reference error, `colors` over pi's 52-token set — 50 required plus optional `scrollbarThumb`→`selectedBg` and `thinkingMax`→`thinkingXhigh` fallbacks); validation wording is pi-verbatim; the `export` section is parsed/validated/retained as passive data (HTML export itself stays Deferred); names containing `/` are rejected (reserved for the automatic pair); the COLORFGBG env default detection is Supported; OSC 11/DSR queries, the automatic `light/dark` pair (slash settings values read as unset, booting pi config dirs identically), auto-sync, and the theme watcher are Deferred with no placeholder (`/reload` is the re-read path). The controller replicates pi's `InteractiveThemeController` subset (boot init, `applyThemeName` with failure → dark + `Failed to load theme "<name>": <error>` + `Fell back to dark theme.`, startup-TUI init, change → editor border color). The `/settings` ThemeSubmenu is a single-mode submenu (no Automatic entry) inside the settings-selector with in-memory preview, global-scope commit, and cancel-does-not-revert (pi quirk); the standalone overlay is deleted. `--theme <path>` (repeatable, missing path → warning, directory scans `*.json`) and `--no-themes` (skips auto-discovery only; explicit paths and builtins unaffected) are Supported with pi semantics and dedupe diagnostics. `ThemeCatalog.*` and `ThemeSettings.*` are deleted; `Theme.*`/`ThemeTokens.inc`/`BuiltinThemes.hpp` are retained as the pi-shaped asset layer (gaining `ScrollbarThumb`, the re-pin, verbatim wording, `export` retention); `ThemeController` re-expresses as the pi controller semantics.

**G6 — completion gate and downstream handoff ([#394](https://github.com/lanshengzhi/cpp-coding-harness/issues/394)).** The tiered gate mirrors #330/#334 with the E2E owned here: capability-to-source checklist in `fixtures/pi-coding-agent/README.md`; lifecycle/ordering/cancellation tests on the enumerated deterministic app surfaces; differential goldens per R2 §6 (harness-driven session suites + value suites pinned as TS snapshots via a committed capture sidecar; System Prompt → C++ golden with the cch identity; interactive/rendering → C++-side only); the **interactive-boot-through-an-agent-turn E2E** (VirtualTerminal-driven boot + fake `ModelRuntime` scripted turn + CLI-level goldens, plus a process-level CLI boot mirroring pi's `stdout-cleanliness.test.ts` containment); bounded manual evidence only (real-terminal smoke + external editor); **SDK/RPC/JSON-removal verification fail-closed** via the Parity Architecture Gate (ADR 0039) extended to the full G1–G5 removal list. Fixtures: committed `fixtures/pi-coding-agent/` mirroring the pi-ai/pi-tui strategy — README pins baseline `83114817` + `@earendil-works/pi-coding-agent@0.83.0` (verified in the frozen checkout), no shard hashes, sanitization rules. Handoff: G1–G5 records + the G6 record are the authority; the phase leaves the map via `/to-spec` → `/to-tickets` → `/implement` with the gate as the final ticket series.

## App-layer baseline re-verification (ADR 0035 obligation, resolved here)

All app-layer baseline pins were re-verified against the frozen pi checkout at `83114817` (byte-level comparisons against `864b35c`, the prior recorded baseline, where the pin named it). **No drift was found in any pinned value contract; two non-contractual deltas and three stale documentation items were observed and are recorded below.**

| Pin | Surface pinned | Verdict at `83114817` |
|---|---|---|
| `src/coding_agent/tui/KeybindingCatalog.cpp:43` ("pi 864b35c, core/keybindings.ts") | App keybinding action table | **No drift** — `core/keybindings.ts` is byte-identical between `864b35c` and `83114817` (same sha1); the pinned table and defaults are unchanged |
| `src/coding_agent/tui/InteractionPolicy.hpp:11` ("pi editor semantics at baseline 864b35c") | Editor submission routing (User Bash parse/busy-restore, compaction steer, streaming steer, ordinary push, escape restore) | **No drift** — the `onSubmit` and `onEscape` handlers are unchanged between the baselines (`!`/`!!` block byte-identical; compaction queue `"steer"`; streaming `prompt(text, {streamingBehavior:"steer"})`; `restoreQueuedMessagesToEditor({abort:true})` on Escape existed at both; the only added call site is the tree-navigation path, a G3-domain behavior) |
| `src/coding_agent/tui/UserBashSyntax.hpp:8` (ADR 0026, pi 864b35c) | `!`/`!!` parse semantics | **No drift** — `interactive-mode.ts` parse is byte-identical (`trim()` → `startsWith("!")` → `slice(1)`/`slice(2).trim()`; empty command falls through; `!!!foo` → excluded `!foo`; busy → `setText(text)` restore + `addToHistory`; `isBashMode = trimStart().startsWith("!")`) |

| ADR 0026/0028 User Bash pins (pi 864b35c raw pipeline) | `bash-executor.ts` `executeBashWithOperations`, `shell-output.ts` `sanitizeBinaryOutput`, `agent-session.ts` `recordBashResult` | **No drift in the pinned values** — `bash-executor.ts` and `shell-output.ts` are byte-identical between the baselines; the `recordBashResult(command, result, options)` call and the raw value pipeline are unchanged. **Non-contractual delta observed:** `executeBash` gains an optional `id` option and emits a new `bash_execution_update {id, delta}` event per chunk, and the single `_bashAbortController` becomes a controller **set** (`abortBash()` aborts all; `isBashRunning` semantics and the TUI's one-bash-at-a-time guard are unchanged) |

**Stale documentation fixed in this pass:** the README claimed User Bash output is "secret-redacted", contradicting ADR 0028's raw pipeline (no redaction of command/output/error-diagnostic values; only the spill-file error diagnostic is bounded-redacted C++ hardening) — corrected; the README's `--enable-bash`-gated `bash` tool and `.cpp-harness/` project markers were superseded by G1/G4 — rewritten; the README SDK/JSON/RPC surface descriptions were charted for removal — removed.

**Facts later work depends on:** the app `*` catalog has **42** actions at `83114817` (R1's "43" corrected by G2); `bash_execution_update` is a new optional event surface the app layer may or may not consume (it duplicates `onChunk` deltas; the pending-bash display already uses `onChunk`); the TUI's one-bash-at-a-time guard still holds because pi's interactive submit path checks `isBashRunning` first.

## Consequences

- **The phase surface is frozen and documented.** This ADR plus the G1–G6 records are the authority for `/to-spec`; the completion gate (#394) makes "done" verifiable for the three provider paths.
- **The app-layer baseline advances to `83114817`** across the README, CONTEXT.md, `docs/keybindings.md`, and the fixture pin references; the stale `864b35c` comments in `src/coding_agent/tui/` die with the files G2 deletes (Transcript, BashBlock, UserBashPresentation, UserBashSyntax, KeybindingCatalog, KeybindingHelp, InteractionPolicy, InterruptAdmission) and are re-verified against `83114817` at implementation for the surviving surfaces.
- **The C++ application surface is a strict pi subset by omission only.** Deleted with no shim: `Sdk.hpp`/`Sdk.cpp`, `RpcMode.cpp`/`RpcJsonl.cpp`, `JsonCliRenderer.cpp`/`JsonEventPrinter.cpp`, `--fake`/`--enable-bash`/`--max-turns`/`--workspace` and their plumbing, `CommandRegistry`/`CommandEffect`/`CommandContext`, `prompt::PromptProcessor` + `transform_context` injection, `KeybindingCatalog`/`KeybindingHelp`, the legacy slash-command registry/effect/context seam, `ThemeCatalog`/`ThemeSettings`, the `.cpp-harness/` project markers, the `ResourceEnablement` policy, the C++ keybinding-doc format. Retained/re-expressed: `InteractiveMode.*` (pi-subset composition), `ClipboardReader.hpp`, `Theme.*`/`ThemeTokens.inc`/`BuiltinThemes.hpp`, the pi `DefaultResourceLoader` subset, `PromptTemplateExpander`/`SkillFormatting` helpers, `parseCommandArgs`-equivalent split semantics.
- **Documentation landed in this pass:** this ADR; CONTEXT.md gains **Print Mode**, **Generic Selector**, **Session Tree Navigation**, **Theme**, **Theme Setting**, and **Theme Submenu** entries; the README's app-layer sections (harness loop, module list, parity direction, CLI states, slash commands, User Bash, SDK section removed, frontend selection, Skills, Native TUI themes/keybindings, project trust, tools, sessions, Deferred) are rewritten to the decided surface; `docs/keybindings.md`'s application section names the pi-canonical 42-action catalog.
- **The pi-coding-agent phase leaves the map** with T1 closed; the destination (an evidence-backed alignment plan and completion route for the three provider paths at `83114817`) is fully charted, and the phase proceeds through `/to-spec` → `/to-tickets` → `/implement`.
