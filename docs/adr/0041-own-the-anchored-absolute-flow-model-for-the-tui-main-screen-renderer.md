# Own the anchored absolute flow model for the TUI main-screen renderer

ADR 0037 aligned the main-screen renderer with pi's `TuiMainScreen` scrollback flow, but the port replaced pi's relative line-flow writes with absolute cursor addressing (`set_cursor` → CUP) while hard-coding the buffer-to-screen origin at row 0 (`viewport_top = 0`, internal cursor `{0,0}`, no startup cursor query). pi's first render (`fullRender(false)`) writes lines joined by `\r\n` from wherever the shell left the hardware cursor and never uses absolute CUP, so it leaves zero residue on any screen state; the C++ port instead overwrites from screen row 0 and leaves any pre-existing shell content below the composed buffer in place until the buffer grows to fill the screen (issue #476 — "dirty-screen startup residue"). The fix must restore pi's observable behavior on dirty screens, but pi's internal model — three mutually-coupled cursor states (`cursorRow` / `hardwareCursorRow` / `previousViewportTop`), relative-only movement with no absolute ground truth, and unrecoverable drift when external output disturbs the cursor — is historical baggage this port need not inherit: the terminal seam here is already absolute-addressing styled, and the input decoder already consumes asynchronous terminal responses (`CSI 16 t` cell-size reports), so a startup Device Status Report can give this renderer the absolute anchor pi never had.

## Considered options

- **Port pi's relative line-flow model faithfully** (first-render `\r\n` flow, relative `\x1b[NB`/`\x1b[NA` movement, tracked hardware cursor in buffer coordinates): rejected — it restores observable parity but imports pi's three-cursor bookkeeping and its silent fragility: any external cursor disturbance desyncs the tracked state permanently, with no recovery path. Relative movement is origin-invariant, which is exactly why pi never needs a cursor query — and exactly why pi can never self-correct.
- **Anchored absolute flow (chosen).** Query the cursor position once at startup (`\x1b[6n`, DSR) with a synchronous probe inside `ProcessTerminal::start`, mirroring the existing appearance probe; establish the exact mapping `scroll_origin_ = r` (screen row of buffer row 0) and `viewport_top_ = max(0, r + N - H)`; then address the first frame and every subsequent write absolutely from the anchor row, so overflow scrolls natively on any screen state and the frame lands where the shell left the cursor. Scrolling happens via CRLF flow only for rows past the visible bottom. Every write is self-correcting — external disturbances are repaired on the next frame — which is a deliberate improvement over pi, not a parity gap.
- **Clear the screen at boot** (`\x1b[2J\x1b[H\x1b[3J` unconditionally): rejected — destroys the shell content pi keeps visible above the frame; ADR 0037 already rejected this for the same reason. It survives here only as the DSR-timeout fallback below.
- **Flow the first render, then track relatively forever** (pi-style fallback as the steady state): rejected — keeps two movement models alive; the fallback must be dumb and certain, not clever and duplicated.
- **Record the residue as a known divergence:** rejected — it violates ADR 0037's stated intent and the `CONTEXT.md` "Main-Screen Scrollback Flow" glossary promise that startup content scrolls away naturally.

## Consequences

- **Startup anchoring.** `ProcessTerminal::start()` issues `\x1b[6n` through the same blocking pre-worker write path as the appearance probe and polls synchronously for the CPR response (`CSI r ; c R`) with a `kCursorPositionTimeout` deadline, returning the reported cursor row as `scroll_origin_`. The input decoder additionally consumes late or duplicate CPR responses (`CSI r ; c R`) without leaking them into the user input stream, alongside the existing `CSI 16 t` consumption. The first frame is written from the reported row — the mechanism is absolute CUP anchored at `scroll_origin_` (the write strategy is unchanged; see below) rather than pi's raw `\r\n` line flow, but the observable placement on a dirty screen is the same: the frame starts at the shell's cursor row and overflow scrolls natively. Afterwards `ProcessTerminal` holds `scroll_origin_` (screen row of buffer row 0) so `screen_row(b) = scroll_origin_ + b - viewport_top_`, and `viewport_top_` advances only via CRLF scroll flow, clear-screen, or the fallback below.
- **DSR timeout fallback.** If no CPR arrives within ~250 ms, the terminal clears screen + scrollback and the origin is set to 0: deterministic, exercised only on terminals that do not answer DSR. The visible cost in that environment is losing on-screen shell content at boot.
- **Self-healing positioning.** After anchoring, every render write is absolutely addressed, so any external cursor disturbance is corrected on the next frame — a recorded improvement over pi, whose relative model drifts unrecoverably.
- **Write strategy unchanged.** Full-width padded lines, writing `firstDiff..end`, and the existing viewport-bounded clear-on-shrink stay as they are. pi's per-line `\x1b[2K`, `firstChanged..lastChanged` write-range optimization, `maxLinesRendered` growth tracking, and overlay-gated clear-on-shrink are recorded as **not ported**: they are byte-level optimizations with no observable symptom here, each already covered by existing goldens.
- **Exit flow.** `Tui::stop()` gains the equivalent of pi's `beforeTerminalStop`: the cursor moves below the composed buffer's last line and emits `\r\n`, so the shell prompt resumes under the transcript instead of overwriting its last line. With the absolute mapping this is a two-line computation.
- **Image placement follows.** `ProcessTerminal::place_image`/`remove_image` convert buffer rows through the anchored mapping like every other positioning operation; fork-B terminal-owned placement (ADR 0037) is otherwise unchanged.
- **Evidence regenerates.** `ScreenStateGoldenTest` gains a dirty-screen boot scenario (pre-existing content with the cursor mid-screen: frame flows from the cursor row, growth scrolls into scrollback, resize full-redraw), `VirtualTerminal` emulates CPR responses plus a no-response timeout case, and the committed e2e goldens (via `tests/coding_agent/tui/InteractiveRenderingGoldenTest.cpp`) stay byte-identical: those scenarios seed no shell content, so `VirtualTerminal` anchors at the default origin 0 and the anchored mapping reduces to the previous absolute model. The full suite must stay green.
- **Verification is end to end:** automated tests plus one manual real-terminal smoke — boot on a dirty screen (no residue), scroll-up over a grown transcript, resize behavior, and exit prompt placement — per ADR 0037's acceptance clause.
- **Out of scope by explicit agreement.** The recorded renderer-side divergences not implicated here (out-of-band `cursor_location()`, caller-set overlay anchors, tolerant Markdown parser, injected `AnimationTimer`, fork-B image placement) remain unchanged; the Termux special-case stays not applicable; `CONTEXT.md`'s "Main-Screen Scrollback Flow" entry keeps its wording, as the promised semantics are unchanged — this ADR makes the implementation finally honor them.
