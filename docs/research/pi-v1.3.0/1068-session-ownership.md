# Application Session ownership — #1068

## Scope

B10 / P6b implements the ownership relocation authorized by [#1068](https://github.com/lanshengzhi/cpp-coding-harness/issues/1068), [#1044](https://github.com/lanshengzhi/cpp-coding-harness/issues/1044) and [ADR 0075](../../adr/0075-align-selected-owner-packages-and-linux-capabilities-with-pi-v1-3-0.md). The selected comparison baseline remains `pi-v1.3.0` / `71023aec1546d6d677a65669c5665c0927ce0dd0`, Linux x86-64 with glibc. This is a preservation slice, with no new upstream parity claim.

## Delivered behavior

`cch_coding_agent` compiles the nine application transcript/history/compaction translation units once: compaction, entry redaction, entry serialization, JSONL storage, journal, resume, store, tree and transcript export. The Session entry/store/tree/resume/compaction interfaces live under `<cch/coding_agent/session/...>`. Their implementation and existing namespace vocabulary are preserved; moved files also receive the formatting required for relocated code.

Five old public headers are exact redirects, named in the manifest's `interface_forwarders` with application ownership, removal ticket #1070 and expiry 2026-12-31. The Gate checks their content and destination, and uses application ownership to judge callers. An application consumer can use the old spelling; core cannot use either spelling. Standalone compilation checks each legacy header using the application Owner's declared interface dependencies without adding an application dependency to core. Eight private test/export headers are checked with the same exact redirect, ticket and expiry policy through `private_forwarders`. The miniature architecture and install fixtures generate both sets of redirects from the production manifest using one shared helper and separate temporary trees.

The shared random hexadecimal ID generator moves to neutral support, preserving its algorithm for session IDs, forks and the remaining core tools. Two named, expiring `session-no-core-private-includes` exceptions retain the journal's core-private POSIX write helper and export's concrete workspace filesystem until #1073 assigns the concrete environment/shared mechanics; other Session sources cannot use those helper includes. Session journal/serialization/redaction policies are unchanged. Ordinary JSONL/memory Agent Sessions remain separate from the independent Durable Runtime, with no new dependency in either direction. Magpie access, the XDG state root, strict no-exception behavior and existing user data are unchanged.
