# Issue 1086 SQLite continuation

## Scope

The continuation tests exercise the public C++ Durable Harness, Session and Transaction operations against frozen pi-v1.3.0 at revision `71023aec1546d6d677a65669c5665c0927ce0dd0`. Live pi tests require a clean frozen checkout supplied by `PI_CHECKOUT`; child processes are bounded by a 30-second timeout. This slice covers SQLite stores and does not execute third-party plugins.

## Delivered behavior

A pi-created SQLite store reopens in C++ with an unfinished task, its checkpoint, documents and revisions. In the live pi→C++→pi path, C++ advances the pending task and pi finishes it. In the C++→pi→C++ path, pi advances the same task and C++ finishes it. The exercised document moves from `n=1` through `n=2` to `n=3`, the task completes with result 17, and the queued submission is settled as unanswered with reason `aborted`. Tests check schema version 1, identifiers, document history and recovered state.

The SQLite writer encodes `tasks.kind`, `submissions.request_id`, `documents.kind` and `documents.key_value` as JSON strings, matching frozen pi's indexed string representation. Recovery strictly decodes these values and rejects malformed or non-string values. The special-character cases include a quote, backslash, non-ASCII character and control byte. The dedicated encoder uses lowercase hex escapes as JavaScript does; the shared JSON writer uses uppercase hex escapes for control bytes, which would differ for SQLite indexed comparisons. C++ lookups delegate to recovered in-memory `StorageState`; `Storage::scan_tasks` has no kind parameter. The live pi driver exercises frozen pi's encoded `scanTasks({kind})`, `submissionByRequest` and `findDocument` predicates against a C++-created store.

A SQLite trigger injects a C++ commit failure on a pi-created store. The test checks rollback of the task, document, submission, sequence and identifiers, then has pi continue the recovered store. This is a controlled transaction failure, not a physical crash or power-loss test.

The candidate [audit-1086 evidence family](../../../fixtures/pi-v1.3.0/audit-1086/manifest.json) contains a frozen-pi-created store and a store generated by the fixed C++ public Harness. The latter store and its IDs are fixture inputs; frozen pi's reads and subsequent advancement are recorded separately as observations. The capture derives the IDs from the produced C++ store. Run `PI_CHECKOUT=/tmp/cch-1080-pi-frozen python3 fixtures/pi-v1.3.0/audit-1086/capture-1086.py build/audit-1086` with a fresh output directory to recapture; the assembler refuses to overwrite registered evidence. ## Remaining boundary

Pre-fix C++ SQLite stores with raw indexed strings are rejected by design; compatibility is claimed for stores written by frozen pi or by the fixed C++ writer. There is no raw/quoted fallback or historical Pike import or migration. The tests do not establish a concurrent-writer guarantee beyond upstream behavior, physical crash or power-loss durability, general Storage parity, or replacement of the ordinary CLI Session.
