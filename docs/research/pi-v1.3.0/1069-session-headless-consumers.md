# Application Session headless consumers — #1069

## Scope

B11 / P6c migrates the headless consumers of the application Session ownership established by [#1068](https://github.com/lanshengzhi/cpp-coding-harness/issues/1068) and [#1044](https://github.com/lanshengzhi/cpp-coding-harness/issues/1044), under [ADR 0075](../../adr/0075-align-selected-owner-packages-and-linux-capabilities-with-pi-v1-3-0.md). The selected comparison baseline remains `pi-v1.3.0` / `71023aec1546d6d677a65669c5665c0927ce0dd0`, Linux x86-64 with glibc. This is a consumer-migration slice: it moves callers and tests onto the application paths and claims no new upstream parity.

## Delivered behavior

Every headless application source now reaches Session through its own Owner Interface spelling. `AgentSession`, its implementation, execution, interaction and compaction translation units, `AgentSessionSnapshot`, `AgentSessionCreationRequest`, `SessionEventCommitment`, `SessionFactory`, `SessionFork`, `SessionLifecycle` and `SessionPersistence` include `<cch/coding_agent/session/...>`; the private Session exports are spelled `coding_agent/session/...`. No headless application source still includes the legacy `cch/agent/harness/session/...` or `agent/harness/session/...` spelling.

The qualified forwards from #1068 stay in place for the not-yet-migrated frontends. `tui/` and `cli/` sources keep the legacy spelling, which the forwarding ownership still resolves to the application owner, and #1070 / P6d removes the forwards with the remaining frontends. No remaining headless old entry is called: the migration changed call sites, not behavior.

The migration is enforced, not just performed. A new Gate rule `application-session-no-legacy-core-session-includes` (`PARITY-8009`) fails any `src/coding_agent/` source outside `tui/` and `cli/` that includes a legacy core Session path, so a later headless caller cannot reintroduce the old spelling without a diagnostic. The rule complements the existing `agent-no-application-session-includes` (`PARITY-8007`, core may use neither spelling) and the expiring `session-no-core-private-includes` exceptions (`PARITY-8008`, still bounded to #1073).

Nine Session and compaction test suites move with their subjects: `tests/harness/session/` and `tests/harness/compaction/CompactionTest.cpp` and `tests/agent/TranscriptExportTest.cpp` become `tests/coding_agent/session/` and `tests/coding_agent/compaction/`, so the owning shard `cch_tests_coding_agent` compiles them and `cch_tests_harness_tools` and `cch_tests_agent` no longer link the application target for them. The moved cases also take the `[coding_agent]` module tag their new owning area requires, so `ctest -L coding_agent` — not the former `harness`/`agent` labels — selects them. `tests/support/SessionEntries.hpp`, `tests/support/SessionSeeding.hpp`, `tests/architecture/PublicHeaderBoundaryTest.cpp` and the evidence pointers in the #1048/#1051/#1056 audits and ADR 0056 follow the same move. Test bodies, names and remaining tags are unchanged.

## Validation

- Focused Validation: `cmake --build --preset vcpkg --target cch_tests_coding_agent cch_tests_harness_tools cch_tests_agent -j4` passed. The owning module label `ctest --preset vcpkg -L coding_agent` selected **1,612** cases and passed **1,612/1,612** (44.92 s); the same label selected **1,450** before the moved cases took their new module tag. The migrated-subject selection `ctest --preset vcpkg -R 'session|Session|compaction|Compaction|transcript export'` selected **437** cases and passed **437/437** (8.74 s). The architecture selection `ctest --preset vcpkg -L architecture` selected **43** cases and passed **43/43** (48.40 s), including `python3 tests/architecture/parity_gate_test.py` at **127/127** cases.
- Behavior is observed through the highest public caller, not through includes. `a persisted session reopened through the frontend seam compacts without rewriting its transcript` (`[issue1069]`) persists a real Session through `create_agent_session_async` with `ExplicitOpenOrCreateSessionTarget`, closes it, reopens it through the same creation seam with `ExplicitResumeSessionTarget` — the path a frontend resume takes — and then compacts it. Normal outcome: reopening restores the seven-message persisted history; compaction appends exactly one `compaction` line; every earlier line stays byte-identical and in file position; the persisted entry agrees with the returned `CompactionResult`; and the reopened session's live context leads with the rebuilt summary. This is the discriminating property a spelling check cannot reach: an include migration that broke resume-time context rebuild would still compile and still match the old spelling, but this case fails.
- The discriminating failure case is `a resumed session whose summarization fails leaves the transcript untouched` (`[issue1069]`). The same reopen path returns a provider error terminal from summarization: compaction settles with `ErrorCode::Stream` and pi's verbatim `Summarization failed: summarizer overloaded` message, the file keeps its exact line count and byte-identical lines, no `compaction` entry exists, and the session stays usable — a retried compaction over the same reopened transcript then appends its single checkpoint while still leaving the original lines untouched. This separates "the checkpoint is written only after the summary succeeds" from "the file was opened for append", which a normal-outcome case alone would not.
- Both cases pass: `ctest --preset vcpkg -L issue1069` selected **2** cases and passed **2/2** (0.18 s).
- `python3 tests/architecture/parity_gate_test.py` passes **127** cases, including the three added for this slice: the checked-in manifest keeps headless application Session sources on their own owner with the `tui/`/`cli/` exclusion; headless application sources, application runtime sources, application Session sources and application Owner Interface headers reach only `PARITY-8009` when they name a legacy core Session path; and a `tui/` source using the retained legacy spelling still produces no diagnostic.
- Full Validation: `cmake --build --preset vcpkg -j4` passed, followed by unfiltered `ctest --preset vcpkg --output-on-failure`: **3,719 selected, 3,718 passed, 1 skipped, 0 failed** (151.54 s). The skipped case is the existing optional `Native TUI differential capture exposes deterministic Pike cells and ANSI`; no new terminal-emulator parity is claimed.
- `scripts/format-check.sh` and `git diff --check` pass.

## Capability status

No capability row changes. This slice relocates consumers and adds an enforcement rule; it observes no new upstream behavior, so membership, implementation and verification statuses in the #1058 ledgers stay as they were — all **1,464** capability rows compare equal before and after rebuilding consolidation; the only ledger differences are the changed `cmake/tests/CodingAgentTests.cmake` input digest, the receipt's `testedRevision`/`recordedAt`, the JUnit digest, and the three `1048-session-persistence` scenario pointers that follow the moved test files. The #1101 receipt was revalidated with its original **14/14** passing comparison selection, and its pinned `1101-validation.xml` was regenerated by that run with an absolute `--output-junit` path (a relative path resolves under `build/` and silently leaves the artifact untouched), so the recorded `testedRevision`, `recordedAt` and JUnit digest all describe the same fresh capture. The `cch_coding_agent:Session:assembly:createAgentSession` and `cch_coding_agent:Session:event-commitment` rows remain `unverified` for the same reason as before — they still carry a C++-regression-only route with no frozen comparison — and the new `[issue1069]` cases are ordinary C++ regressions, not a frozen-capture comparison, so they do not advance that status.

## Remaining boundary

#1070 / P6d migrates the CLI and Native TUI consumers and removes every temporary Session forward, including the manifest records, the miniature-fixture mirrors and the standalone-compilation treatment. Until then the `tui/` and `cli/` sources keep the legacy spelling and the `PARITY-8009` rule keeps them out of scope by `excluded_source_prefixes`. The concrete environment/tool migration #1073 removes the two residual private-helper exceptions still dated to it. #1044 remains open and is not edited by this slice.
