# Issue 1085 JSONL filesystem boundary probe

The public `JsonlStorage::open` contract describes publication, recovery and poisoned-instance behavior, but does not specify whether the store directory or its ancestors may be symlinks. ADR 0075 targets Linux and forbids deleting user data. The architecture security section retains a no-follow policy; ADR 0057 describes tool path resolution, and ADR 0064's symlink-refusing parent walk applies to the separate application Session store. Those decisions do not by themselves specify the Durable directory compatibility contract.

The shared `JsonlStorage.cpp` helpers serve `main.jsonl`, document and task sidecars. Recovery enumerates the directory using `directory_iterator`, reads with `ifstream`, truncates partial and unconfirmed tails using `resize_file`, and uses path-based removal or temporary-file replacement for reclamation. Commits append sidecars then the main marker and reclaim after the marker is published; failed append poisons the instance, while reclamation after successful publication is best effort. Existing `ifstream`, `ofstream`, `resize_file` and directory traversal follow links. Numeric sidecar filenames prevent path injection but do not prevent filesystem aliasing.

Two independent temporary-directory public probes create a store-side `task-2.jsonl` alias to an outside file containing `complete\npartial`. A symbolic link and a hard link each cause `open` to fail only after truncating the outside target to `complete\n`: each test selected 1, passed 0, failed 1, skipped 0. The retained outputs are [symlink RED](1085-captures/symlink-red.txt) and [hard-link RED](1085-captures/hardlink-red.txt); trailing whitespace in the CTest output was removed. Both external targets were disposable test files. No production fix has been accepted yet.

A candidate Linux design opens and retains a directory descriptor for the store lifetime, enumerates relative to that descriptor, and uses single-component `openat` names with `O_NOFOLLOW`, `O_CLOEXEC` and `fstat` regular-file checks. Reads and their truncations must use the same file descriptor, and writes must open with no-follow at the actual append; replacement and deletion use descriptor-relative `renameat`/`unlinkat` so a terminal symlink is not followed. A checked descriptor avoids a `stat`/`open` race. In the current error model, unsafe or unreadable paths on open reject with a Validation corruption error; an append failure poisons the live instance. Reclamation still happens after marker publication and does not change a successful commit's result.

This design requires a decision about the store path: a final-component no-follow directory open leaves ancestor symlinks permitted; a no-follow parent walk rejects them and may change accepted input paths. Holding the descriptor protects against a later pathname replacement redirecting operations, but not mutation of the directory's entries by another process. A link count check can reject files already hard-linked at inspection; it cannot alone prevent another process from creating a hard link after that check. Frozen `packages/durable/README.md:682` states: “One process owns a storage at a time; there is no cross-process locking.” ADR 0075 says concurrent cross-process writers are not implicitly promised beyond upstream. Neither text rules out external filesystem mutation or defines it as trusted. The no-user-data-loss requirement therefore cannot be declared met for hard links and concurrent replacement on the basis of no-follow alone. Resolve the required trust and concurrency boundary or split the broader filesystem hardening work before claiming completion.

A separate frozen public `openNodeJsonlStorage` probe used the same stable aliases and disposable outside bytes. Frozen pi ignored the symlink and opened successfully without changing the target. It followed the hard link, truncated its partial tail and then raised `JsonlCorruptionError` on the malformed complete line; the outside target changed. The reproducible [probe](1085-captures/frozen-link-probe.mts) and [output](1085-captures/frozen-link-probe.txt) are retained. Rejecting a stable symbolic or multiple-link file without modifying it is therefore an intentional safety divergence, not frozen parity. Ordinary singly linked store files must remain interoperable and keep the published-prefix and error behavior described above.

The smallest task-only candidate opens each `task-N.jsonl` with `O_NOFOLLOW`, checks `fstat` for a regular file and `st_nlink == 1`, then reads and truncates through that same descriptor. A missing file retains missing-confirmed-marker corruption behavior; a stable symlink or multiply linked file instead fails closed with a Validation error. For appends, use the same no-follow and link-count checks on the writable descriptor before writing. Reclamation can unlink the directory entry without following a symlink, but must not remove a replacement entry without an identity check; a failure remains best effort after successful publication. Normal singly linked files remain compatible. A hard link created after `fstat` can still make the subsequent write or truncation affect another name for the inode; neither a descriptor nor one-owner storage contract rules that out. The directory and existing main/document paths need separate Owner-level design before expanding this change.

Verification must include independent outside-byte checks for links to main, task and document paths, writes, reads and both truncation paths; the temporary reclaim path; normal recovery; marker failure; and publication with failed best-effort reclamation. Preserve original evidence families and receipts. Full Validation remains blocked pending review and evidence disposition.
