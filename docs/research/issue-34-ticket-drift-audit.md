**Audit point:** repository `d95087d4998222f3b0ce37c3e7c7c57750b8bbb1`; changes reviewed from baseline `4eb5f443eb29f41cebdd576cb4cd478c659acb6b` after `2026-07-23T14:31:24Z`.
**Tracker scope:** [#34](https://github.com/lanshengzhi/cpp-coding-harness/issues/34), children [#35–#64](https://github.com/lanshengzhi/cpp-coding-harness/issues/35), and remediation [#65–#81](https://github.com/lanshengzhi/cpp-coding-harness/issues/65).
**Method:** primary issue bodies/comments/dependency metadata, the 28 commits in the stated range, current public headers/source/tests/CMake/docs, accepted ADRs 0005, 0011, 0018, and 0020–0025, the local pi source at recorded baseline `864b35c`, and the current parity map #2. No implementation or tracker edits were made.

## Executive conclusion

The Native TUI plan has **not drifted at the product boundary**: ADR 0025 still requires a reusable public TUI module plus a separate coding-agent interactive module, and current `CMakeLists.txt` contains no TUI target or TUI source/test entries. Tickets #45–#64 therefore remain predominantly valid future work.

The material drift is in the backend groundwork. #35–#38 remain correctly closed, but remediation #65–#81 changed several authoritative seams after their closure: queues now have published Agent configuration bounds, the Execution Environment is the complete pi-shaped `AsyncExecutionEnv`, process execution is owned by `AsyncProcessRunner`, model identity is `ai::Model`, and bounded/redacted presentation is mandatory. Consequently #41, #42, and #44 are partly satisfied; #40, #58, #62, #64, and parent #34 need wording/dependency reconciliation.

There is also a pre-existing blocker omitted from the child-ticket set: accepted ADR 0018 requires awaitable, move-only Agent policy hooks, but the current hook typedefs are synchronous. #39 already assumes cancellation reaches “awaitable policy hooks,” so it is not implementation-ready unless a new remediation ticket precedes it or its scope is expanded substantially. #41 has a wording mismatch rather than an open architecture decision: accepted ADR 0011 already defines `close()` as a synchronous, non-blocking close request whose teardown is deferred until quiescence. The ticket should say that explicitly instead of implying that a callback must block waiting for itself.

## Current-state evidence

1. **Stateful Agent groundwork remains intact.** `include/cch/agent/Agent.hpp` exposes the stateful `Agent`, passive `state()`, move-only subscription, and async string prompt. `src/coding_agent/runtime/AgentSessionRuntime.{hpp,cpp}` composes that Agent and carries no second history/subscriber registry. The `Agent` interface surface is pinned by `owner_interface_standalone`/`PublicHeaderBoundaryTest` and the runtime seam tests (`AgentTest`, `ModelRuntimeSeamTest`), and the Parity Architecture Gate (ADR 0039) now fails closed on any reintroduced unclassified/unknown target, root, or source in the composition. These are the end states of [`41d5b287`](https://github.com/lanshengzhi/cpp-coding-harness/commit/41d5b2877c84b2fdf2e2a34316dc02d4ad1cbaee), [`b9d88fd8`](https://github.com/lanshengzhi/cpp-coding-harness/commit/b9d88fd8e37f185caff3c63052c390666bc7d2b6), and [`ef1042d2`](https://github.com/lanshengzhi/cpp-coding-harness/commit/ef1042d289e5908902ae2803de289a83c5fb99fd).
2. **Prompting remains async-first.** `include/cch/coding_agent/Sdk.hpp` publishes `AgentSession::prompt()` as `boost::asio::awaitable<util::ExpectedVoid>` and separately names `prompt_blocking()`, matching [`9583af1a`](https://github.com/lanshengzhi/cpp-coding-harness/commit/9583af1a05d454adcf415e2de8b4b617e7164150). `tests/coding_agent/SdkSessionTest.cpp` remains the fake-provider/executor coverage seam.
3. **Cancellation is still absent.** Neither `Agent` nor `AgentSession` exposes `abort`; `AsyncExecutionEnv` methods and `ExecOptions` in `include/cch/harness/ExecutionEnv.hpp` carry no `std::stop_token`; `ProcessRequest` in `src/util/Process.hpp` carries no stop token. Thus #39–#40 are not accidentally implemented. `CODING_STANDARDS.md §6.4` now makes the intended mechanism explicit: cancellation flows through `std::stop_token` and close/abort are idempotent.
4. **The awaitable-hook prerequisite is still absent.** ADR 0018 requires move-only policy callables returning `boost::asio::awaitable<std::expected<...>>`, with synchronous adapters. In contrast, `BeforeToolCallHook` and `AfterToolCallHook` in `include/cch/agent/AgentTool.hpp` and every hook in `include/cch/agent/AgentContext.hpp` return synchronous `util::Expected` values. The recorded pi baseline awaits transformation, tool, and next-turn hooks and passes the active abort signal. No dedicated issue implements ADR 0018; #39 merely assumes it. This is a missing backend child ticket, not a TUI design change.
5. **Close is already partially two-phase.** `AgentSessionRuntime::close()` clears subscriptions, changes an active session to `Closing`, and delays `agent_.reset()`/owned-environment cleanup until the active `run_prompt()` scope exits. `Sdk.hpp` documents a shared active prompt frame for callback-safe destruction. However, close does not request cancellation. ADR 0011 already resolves the API semantics: `close()` remains a non-blocking request, including from callbacks, while teardown occurs after quiescence. #41 should narrow itself to cancellation, admission rejection, cleanup ordering, and observable eventual settlement rather than invent an awaitable close.
6. **Snapshot work has a strong internal base but no SDK snapshot.** `Agent::state()` returns `AgentState` with messages, running/streaming/tool/model/thinking/diagnostic state (`include/cch/agent/AgentContext.hpp`). `AgentSession` exposes only `message_count()`, `last_assistant_text()`, and scalar metadata; there is no passive `AgentSessionSnapshot`. #42 is therefore partly, not fully, satisfied.
7. **Queue groundwork moved ahead of #44.** [`b48318d1`](https://github.com/lanshengzhi/cpp-coding-harness/commit/b48318d1521f17f37f0b202d4bc61a903f93a912) added `AsyncAgentOptions::max_queued_messages{256}` and `max_queued_bytes{16 MiB}` and queue diagnostics/tests. The public `Agent`/`AgentSession` still exposes no `steer` or follow-up operation, and `AgentState` does not publish the configured bounds. #44’s bounds criterion is partly satisfied and should not be reimplemented.
8. **Execution terminology changed.** [`4b31c54e`](https://github.com/lanshengzhi/cpp-coding-harness/commit/4b31c54eedf0fa7820f0669326263f1bda7f9379) removed the tool-shaped/default-`NotSupported` execution surface; `include/cch/harness/ExecutionEnv.hpp` now defines the complete `AsyncExecutionEnv` plus `exec`. [`3f0facb4`](https://github.com/lanshengzhi/cpp-coding-harness/commit/3f0facb4a468f4ae11147bb202c35f0955811958) renamed the process seam to `AsyncProcessRunner`. #40 should name these authoritative seams rather than generic “filesystem capabilities and process execution.”
9. **Message and model vocabulary was tightened.** [`60b92783`](https://github.com/lanshengzhi/cpp-coding-harness/commit/60b92783716527b20b6d2f23fa80feecda92a98f) made model identity `ai::Model`. [`d95087d4`](https://github.com/lanshengzhi/cpp-coding-harness/commit/d95087d4998222f3b0ce37c3e7c7c57750b8bbb1) reconciled accepted ADR 0005: the physical live-message value is the shared `cch::ai::MessageVariant`, containing provider-ready forms plus exactly four extended runtime forms. TUI tickets may keep the domain term **Agent Message**, but file/API criteria should cite `ai::MessageVariant`, `ai::Content`, and `ai::ImageContent` rather than imply a second coding-agent message type.
10. **Security acceptance should reuse the remediated seams.** [`c8e31167`](https://github.com/lanshengzhi/cpp-coding-harness/commit/c8e3116720eaea58f5335ad2d4ff5d22619bff0d), [`77ba8202`](https://github.com/lanshengzhi/cpp-coding-harness/commit/77ba820254f14cfa9f0ab407b7afd50520732046), [`04b25a65`](https://github.com/lanshengzhi/cpp-coding-harness/commit/04b25a652be39462eba0db8e49c5bcbd8457dde1), and [`7bb3341c`](https://github.com/lanshengzhi/cpp-coding-harness/commit/7bb3341cd460ebe2f2511356f25a24c46ea6ceb9) hardened redact-before-bound behavior. `CODING_STANDARDS.md §§10.1–10.3` now prohibit ad-hoc presentation truncation. #34/#45–#64 are compatible but should cite these exact seams in diagnostics/transcript acceptance.
11. **No TUI implementation has landed.** Current `CMakeLists.txt` defines `cch_util`, `cch_ai`, `cch_agent`, `cch_harness`, `cch_tools`, and `cch_coding_agent_runtime`; it has no `cch_tui`, interactive-mode TUI target, Virtual Terminal, or TUI tests. The post-cutoff changed-file set likewise contains no TUI path. Accepted `docs/adr/0025-own-a-modular-native-tui.md` still matches #34.
12. **CLI names are not yet the planned final modes.** `src/cli/CliConfig.hpp` has `OutputMode::{Text,Json,Rpc}` plus `bool repl`; `src/cli/CliParse.cpp` accepts `--mode text|json|rpc`, `--repl`, and automatically changes an empty text prompt to REPL. There is no `Tui` or separately named `Print` intent. #34/#54/#64 should specify the migration from these exact current intents rather than speak as if “explicit line-oriented” and “print” already exist.
13. **A current documentation inconsistency should not be copied into #64.** `README.md` still says the loop repeats “until … the max-turn limit is reached,” although [`b48318d1`](https://github.com/lanshengzhi/cpp-coding-harness/commit/b48318d1521f17f37f0b202d4bc61a903f93a912) made the default uncapped. #64’s final documentation audit should include this existing stale statement, but fixing it is not TUI implementation work.

## Dependency audit

GitHub dependency metadata is internally consistent: every recorded edge points from a child to the ticket named in its body, and there are no detected cycles. Closed #35–#38 remain recorded as blockers of descendants (#36–#39, #42–#44, #58); that history is accurate, but the open tickets should describe them as **satisfied prerequisites** so agent planning does not mistake them for active work.

Three semantic dependency gaps remain:

- **ADR 0018 → #39/#40:** #39 assumes awaitable cancellation-aware hooks, but no issue migrates the synchronous hook contracts. Add a new backend child ticket and make #39 (and therefore #40) depend on it.
- **#41 → #58/#61:** the dependency is right, but #41 should use ADR 0011's already-decided non-blocking close-request semantics rather than saying a callback “waits.”
- **#44 → #62:** queue operations alone do not fulfill #62’s “advertises Supported Capabilities” criterion. Capability availability must come from #42/#44 or #62 must define derivation from the assembled public surface.

No direct dependency needs to be added among #45–#57: their DAG is still coherent. #64’s direct blockers cover the final integration capabilities transitively.

## Recommended adjustments

### Tracker-only; safe without product decisions

1. Add a focused backend child ticket implementing accepted ADR 0018 (awaitable move-only policy hooks, synchronous adapters, executor/order/cancellation tests); make #39 and #40 depend on it.
2. Mark closed #35–#38 dependencies as satisfied prerequisites in open-ticket prose while retaining dependency metadata/history.
3. Update #40’s names and file references to `include/cch/harness/ExecutionEnv.hpp` (`AsyncExecutionEnv::exec`, `ExecOptions`) and `src/util/Process.hpp` (`AsyncProcessRunner`, `ProcessRequest`).
4. Align #41 with accepted ADR 0011: `close()` is a non-blocking request, active work is cancelled when supported, admission closes immediately, and teardown occurs exactly once after quiescence.
5. Update #42 to reuse `Agent::state()`/`AgentState` and prohibit duplicate live state.
6. Update #44 to credit #68/`b48318d1` for published queue defaults/internal validation, leaving Agent-owned queue storage, host-facing enqueue/clear/mode operations, admission results, and capability exposure open.
7. Update #58/#59/#63 physical API terminology to ADR 0005’s shared `ai::MessageVariant`, `UserMessage`, `ToolResultMessage`, and `ImageContent`, while retaining glossary terms in user-facing prose.
8. Add explicit references in #34/#58/#61/#64 to `CODING_STANDARDS.md §§6.4 and 10.1–10.3` for stop-token cancellation and bounded/redacted presentation.
9. Amend #34’s status/further notes: #35–#38 and conformance #65–#81 are complete; #39–#44 plus the new hook-remediation ticket remain backend prerequisites; no TUI implementation has started.
10. Make #60/#64 cite parity map #2's open User Bash placeholder and keep it absent from Native TUI command/help/keybinding surfaces.
11. Add the stale README max-turn sentence to #64’s final documentation checklist.

### Requires user confirmation before tracker amendment

1. **Capability advertisement (#42/#44/#62):** choose a passive capabilities field in the Agent Session snapshot, operation-presence/assembly as the source of truth, or another narrow value contract. Do not introduce inert flags.
2. **Final CLI intent names (#54/#64):** decide whether to extend `OutputMode` with `Tui`, add separate `--tui`/`--text` flags, or use another mutually exclusive passive intent. Current public behavior is `--repl` plus `--mode text|json|rpc`; tracker text should not pre-decide an incompatible syntax. A separate `Print` enum is unnecessary unless it carries behavior distinct from positional text mode.
3. **Cancellation shape across `AsyncExecutionEnv` (#40):** confirm whether every filesystem operation receives a stop token or only interruptible hooks/tools/`exec` do. The current ticket says filesystem capabilities broadly, while safe-point semantics may not justify changing every filesystem signature.
