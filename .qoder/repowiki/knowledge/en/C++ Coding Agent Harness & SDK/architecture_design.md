- **Layered Package Architecture**: The system is split into distinct CMake targets (`cch_util`, `cch_ai`, `cch_agent`, `cch_harness`, `cch_tools`, `cch_coding_agent_runtime`) that enforce a strict dependency direction from low-level utilities up to the runtime orchestration layer.
- **Public/Private Boundary**: Public contracts reside in `include/cch/` (passive value structs, abstract interfaces like `StreamingChatClient`), while implementation details (Glaze DTOs, Boost.Beast transport, CLI parsing) are kept private in `src/` and linked via `PRIVATE` include paths.
- **Capability Seams**: Core capabilities such as chat streaming, file system access, and process execution are defined as abstract interfaces or dependency-injected services, allowing for fake providers and sandboxed local execution environments.
- **Event-Driven Agent Loop**: The core `AsyncAgentLoop` uses move-only callback semantics (`AgentEventSink`) for lifecycle events, enabling unique state ownership without shared pointers, and supports both sequential and parallel tool execution modes.
